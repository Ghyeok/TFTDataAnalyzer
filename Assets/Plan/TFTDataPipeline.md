# TFT 데이터 분석 도구 설계

작성일: 2026-09-17  
상태: 설계 확정

## 1. 목적

이 Unity 프로젝트는 Teamfight Tactics(TFT)의 시즌·패치별 정적 데이터와 과거 경기 결과를 수집하고, 익명화된 집계 통계를 제공하는 데이터 분석 도구다.

첫 지원 대상은 Set 18이다. 이후 과거 시즌과 미래 시즌을 동일한 데이터 팩 규격으로 추가할 수 있어야 한다. 기존 패치 데이터는 덮어쓰지 않으며, 모든 통계에는 시즌, 패치, 지역, 티어, 표본 수, 수집 기간을 표시한다.

이 프로젝트는 전투를 실행하거나 결과를 계산하지 않는다. 실제 전투 시스템에 관한 기술 연구는 Riot Games의 명칭, 데이터, 설명문, 아이콘 및 기타 IP를 사용하지 않는 별도의 Unity 프로젝트에서 창작 샘플 데이터로 진행한다.

## 2. 제품 경계

### 2.1 포함 범위

- 패치별 기물, 시너지, 아이템, 증강 데이터 탐색
- 한국어 표시 데이터와 영어 원문 연결
- 패치 간 추가·변경·삭제 항목 비교
- 과거 경기의 익명화된 집계 통계
- 기물, 시너지, 아이템, 증강 조합별 평균 최종 순위
- 조합별 Top 4 비율과 1위 비율
- 같은 로비에 두 조합이 존재했을 때의 상대 배치 우위율
- 모든 비율 지표의 표본 수와 신뢰구간 표시

### 2.2 제외 범위

- 전투 규칙 재현 또는 가상 전투 실행
- 전투 승패 확률의 계산 또는 미래 결과 예측
- 라운드별 맞대결 승률 표시
- 현재 게임 상태, 보드, 상점 또는 상대 정보 수집
- Spectator API, 화면 인식, 클라이언트 메모리 접근 및 인게임 오버레이
- 플레이 중 행동을 지시하는 추천
- 플레이어 검색, 프로필, 이름, PUUID 등 개인 식별 정보 표시
- Riot 정책에서 금지한 Legends 및 Legend 기반 증강 승률 표시

## 3. 용어와 지표 정의

### 3.1 관측 조합

한 참가자의 경기 종료 시점 기물, 성급, 장착 아이템, 활성 시너지 및 증강으로 구성된 최종 상태다. Match API가 경기 도중의 모든 보드 변화를 제공하지 않으므로, 이 값은 전체 경기 동안 사용한 조합을 의미하지 않는다.

### 3.2 평균 최종 순위

같은 조건으로 분류된 관측 조합의 최종 순위 산술평균이다. 낮을수록 높은 성과를 뜻한다.

### 3.3 Top 4 비율

관측 조합 가운데 최종 순위가 1위부터 4위인 경기의 비율이다.

### 3.4 1위 비율

관측 조합 가운데 최종 순위가 1위인 경기의 비율이다.

### 3.5 상대 배치 우위율

같은 로비에 조합 A와 조합 B가 함께 관측된 경기 중 A의 최종 순위가 B보다 높았던 비율이다. 이는 실제 라운드 전투의 승률이나 미래 전투 결과의 예측값이 아니다. UI와 내보내기 결과에서 `전투 승률`, `승패 확률`, `예측`이라는 이름으로 표시하지 않는다.

### 3.6 신뢰구간과 최소 표본

비율 지표는 95% Wilson 신뢰구간을 함께 표시한다. 기본 최소 표본 수는 100건이며, 그보다 적은 경우 비율을 숨기고 `표본 부족`으로 표시한다. 최소 표본 기준은 분석 설정으로 높일 수 있지만 100 미만으로 낮출 수 없다.

## 4. 정책 및 IP 안전 경계

- 정적 데이터와 이미지의 1차 출처는 Riot Data Dragon으로 제한한다.
- CommunityDragon은 Data Dragon에 없는 정적 필드의 보완 출처로만 사용한다.
- 경기 결과 데이터는 공식 Riot Match API에서만 수집한다.
- CommunityDragon 데이터는 필드별 출처를 기록하고 공식 값보다 우선하지 않는다.
- 원본 설명문과 아이콘은 분석 화면에 필요한 범위에서만 사용한다.
- Riot 원본 데이터와 이미지를 별도 데이터 상품으로 재배포하지 않는다.
- 프로젝트가 외부 사용자에게 제공되기 전 Riot Developer Portal에 제품을 등록하고 당시의 최신 정책을 다시 검토한다.
- 외부 제공 시 Riot이 요구하는 최신 비공식 프로젝트 고지문을 눈에 잘 띄는 위치에 표시한다.
- 정책 검토일과 확인한 정책 URL을 메타데이터에 기록한다.
- 정책이 바뀌거나 등록 상태가 유효하지 않으면 외부 데이터 갱신과 배포를 중단할 수 있어야 한다.

## 5. 시스템 구성

```text
Riot Data Dragon --------+
                         +--> 정적 데이터 수집기 --> 정적 카탈로그
CommunityDragon(보완) ---+                            |
                                                      +--> 통계 조인 --> 분석 저장소 --> Editor UI
Riot Match API -----------> 경기 수집기 --> 익명화 --> 집계기
```

### 5.1 정적 데이터 수집기

특정 패치의 한국어·영어 정적 데이터를 내려받고 원본 URL, 다운로드 시각, ETag, SHA-256 및 게임 빌드 버전을 기록한다. 공식 소스와 보완 소스는 독립 어댑터로 구현하여 어느 한쪽의 형식 변경이 다른 쪽이나 내부 모델에 직접 전파되지 않게 한다.

### 5.2 정적 카탈로그

외부 데이터를 안정 ID 기준의 내부 표준 모델로 변환한다. 시즌과 패치별 카탈로그는 불변 스냅샷이며 새 패치가 기존 카탈로그를 수정하지 않는다.

### 5.3 경기 수집기

사용자가 제공한 Riot 개발 API 키로 Match API를 호출한다. 수집기는 API의 지역 라우팅, 호출 제한, 재시도 지시 및 최신 데이터 우선 권고를 준수한다. 개발 API 키는 짧은 유효기간과 제한된 호출량을 전제로 한다.

### 5.4 익명화 계층

응답을 받은 즉시 플레이어 이름과 PUUID를 제거한다. Match ID는 중복 수집 방지를 위한 SHA-256 해시로 변환하고 원문을 보존하지 않는다. 통계에 필요한 최종 순위, 마지막 라운드, 최종 기물·아이템·시너지·증강, 패치, 큐 및 지역만 다음 단계로 전달한다.

### 5.5 집계기

익명화된 관측을 패치, 지역, 티어, 큐 및 조합 키별로 집계한다. 집계 결과에는 합계와 비율만이 아니라 분자·분모, 수집 기간, 데이터 버전 및 신뢰구간 계산에 필요한 값을 보존한다.

### 5.6 분석 저장소

정적 카탈로그, 익명화된 관측, 사전 계산 집계 및 수집 체크포인트를 분리해 저장한다. 원본 Match API 응답은 디스크에 기록하지 않고 메모리 스트림에서 읽은 뒤 즉시 익명화한다. 통계 스키마가 변경되면 익명화된 관측에서 집계를 재생성할 수 있다.

### 5.7 Editor UI

Unity 메뉴의 `TFT Data Analyzer` 창에서 데이터 업데이트, 수집 상태, 검증 결과, 패치 변경점 및 집계 통계를 확인한다. Editor 시작 시에는 하루 한 번 새 정적 패치 존재 여부만 비차단 방식으로 확인하고, 다운로드와 반영은 사용자가 명시적으로 실행한다.

## 6. 정적 데이터 모델

### 6.1 패치 매니페스트

- `schemaVersion`: 내부 데이터 스키마 버전
- `setId`, `setNumber`, `setName`
- `patchId`: TFT 패치 식별자
- `sourceGameVersion`: 원본 게임 빌드 버전
- 생성 시각과 전체 콘텐츠 해시
- 소스별 URL, 다운로드 시각, ETag 및 SHA-256
- 정책 검토일과 정책 URL
- 검증 오류·경고 수
- 이전 패치 대비 추가·변경·삭제 요약

### 6.2 기물

- 안정 ID, 한국어·영어 표시 이름
- 비용, 역할 및 연결된 시너지 ID
- 공개된 기본·성급별 능력치
- 스킬 설명과 정적 효과값
- 공식 아이콘 참조
- 필드 출처와 보완 여부

### 6.3 시너지

- 안정 ID, 한국어·영어 표시 이름
- 활성 구간과 구간별 정적 효과값
- 설명과 공식 아이콘 참조
- 필드 출처와 보완 여부

### 6.4 아이템

- 안정 ID, 한국어·영어 표시 이름
- 조합식, 제공 능력치 및 정적 효과값
- 고유·중복·장착 제한 조건
- 공식 아이콘 참조
- 필드 출처와 보완 여부

### 6.5 증강

- 안정 ID, 한국어·영어 표시 이름
- 등급, 설명 및 정적 효과값
- 관련 기물·시너지·아이템 참조
- 공식 아이콘 참조
- 필드 출처와 보완 여부

### 6.6 현지화

문자열은 안정 ID와 필드명을 키로 하여 레코드 본문과 분리한다. `ko-KR`과 `en-US`를 함께 보존하고 한국어가 없을 때 영어로 대체했는지 기록한다.

## 7. 병합 규칙

1. Riot 공식 값이 존재하면 우선한다.
2. 공식 필드가 없거나 비어 있을 때만 CommunityDragon 값으로 채운다.
3. 값이 충돌하면 공식 값을 선택하고 양쪽 값과 결정 결과를 병합 보고서에 남긴다.
4. 모든 관계는 표시 이름이 아니라 안정 ID로 연결한다.
5. 내부 모델에 포함하지 않은 원본 필드는 실행 가능한 데이터로 승격하지 않고 출처가 표시된 확장 데이터로 격리한다.
6. 동일 입력으로 다시 생성하면 동일한 정규화 JSON과 콘텐츠 해시가 나와야 한다.

## 8. 저장 및 보안

### 8.1 프로젝트 자산

- 검증된 패치 매니페스트와 정규화된 정적 카탈로그
- Unity 분석 UI에서 사용하는 ScriptableObject 인덱스
- 필요한 공식 아이콘과 출처 메타데이터
- 분석 스키마와 창작 테스트 픽스처

### 8.2 로컬 캐시

정적 데이터 원본, 임시 다운로드 및 실패 보고서는 `Library/TftAnalyzerCache`에 저장한다. 원본 Match API 응답은 이 캐시에 기록하지 않는다. `Library`는 버전 관리와 Unity 빌드에 포함하지 않는다.

### 8.3 API 키

API 키는 프로젝트 파일, `EditorPrefs`, 로그 또는 명령줄 인자에 기록하지 않는다. 환경 변수 또는 OS 자격 증명 저장소에서 읽으며 오류 메시지와 진단 로그에서 마스킹한다.

### 8.4 익명 통계 저장소

익명화된 관측과 집계 결과는 `Library/TftAnalyzerStore` 또는 사용자가 지정한 프로젝트 외부 경로에 저장한다. Unity 빌드와 버전 관리에 자동 포함되지 않으며 내보내기는 사용자의 명시적 동작으로만 수행한다.

## 9. 데이터 흐름

### 9.1 정적 패치 업데이트

1. 하루 한 번 공식 버전 목록을 조회한다.
2. 지원 시즌에 대응하는 새 게임 빌드가 있는지 확인한다.
3. 사용자에게 변경 가능성을 알린다.
4. 사용자가 다운로드를 승인한다.
5. 한국어·영어 공식 데이터를 임시 캐시에 내려받는다.
6. 사용자가 보완 소스를 허용한 경우에만 CommunityDragon 데이터를 내려받는다.
7. 각 원본의 해시와 메타데이터를 기록한다.
8. 변환, 병합 및 참조 검증을 수행한다.
9. 검증 성공 시 새 불변 패치 팩을 생성한다.
10. 사용자가 분석 대상 기본 패치를 선택한다.

### 9.2 경기 통계 수집

1. API 키 존재와 유효성을 확인한다.
2. 사용자가 지역, 큐, 패치 및 수집 한도를 선택한다.
3. 정책과 호출 한도를 표시하고 수집 승인을 받는다.
4. Match ID 목록과 경기 응답을 호출 제한 안에서 가져온다.
5. 응답을 즉시 익명화하고 중복을 제거한다.
6. 정적 카탈로그의 안정 ID와 조인한다.
7. 유효한 관측을 저장하고 집계를 갱신한다.
8. 원본 응답을 보유한 메모리 버퍼를 해제한다.
9. 수집 건수, 제외 건수, 오류 및 다음 재시도 가능 시간을 표시한다.

## 10. 검증 규칙

### 10.1 정적 데이터

- 중복 안정 ID가 없어야 한다.
- 모든 기물의 시너지 참조가 존재해야 한다.
- 아이템 조합 재료와 증강 관련 참조가 존재해야 한다.
- 비용과 활성 구간 등 정수 범위가 유효해야 한다.
- 한국어 또는 영어 표시 문자열이 최소 하나 존재해야 한다.
- 이미지 파일의 형식과 해시가 유효해야 한다.
- 패치와 시즌을 이름 패턴만으로 확정하지 않고 레코드 구성도 교차 검증해야 한다.

### 10.2 경기 데이터

- Match API 데이터 버전을 기록한다.
- 패치, 큐, 최종 순위 및 기물 목록이 없는 관측은 제외한다.
- 참가자 수와 최종 순위 값의 일관성을 확인한다.
- 정적 카탈로그에 없는 안정 ID는 삭제하지 않고 격리 보고서에 남긴다.
- 동일 Match ID 해시는 한 번만 집계한다.
- 익명화 전 응답이 디스크, 로그 또는 오류 보고서에 기록되지 않아야 한다.

### 10.3 통계

- 분자와 분모가 집계 원본과 일치해야 한다.
- 최소 표본 미만의 비율은 노출하지 않아야 한다.
- 신뢰구간 계산이 알려진 테스트 벡터와 일치해야 한다.
- 패치, 지역, 티어 및 큐가 다른 표본을 묵시적으로 합치지 않아야 한다.
- 상대 배치 우위율을 라운드 전투 승률로 표현하지 않아야 한다.
- 정책상 금지된 지표가 UI와 내보내기에 나타나지 않아야 한다.

## 11. 오류 처리

- 네트워크 오류: 지수 백오프를 적용하되 사용자가 취소할 수 있게 한다.
- HTTP 429: `Retry-After`를 존중하고 자동 재시도 시점을 표시한다.
- 인증 오류: 수집을 중단하고 키를 로그에 남기지 않은 채 재설정을 안내한다.
- 외부 스키마 변경: 해당 소스 어댑터만 실패 처리하고 기존 패치 팩을 유지한다.
- 병합 충돌: 공식 값을 유지하고 충돌 보고서를 생성한다.
- 검증 실패: 부분 데이터 팩을 활성화하지 않는다.
- 익명화 실패: 원본 경기 응답을 어디에도 저장하지 않고 메모리 버퍼를 즉시 해제한다.
- 집계 실패: 익명화된 관측은 유지하고 집계만 다시 생성한다.

## 12. Editor UI

### 12.1 데이터 관리

- 지원 시즌과 패치 목록
- 새 패치 확인과 사용자 승인 다운로드
- 소스별 버전, 해시, 수집 시각 및 검증 상태
- CommunityDragon 보완 사용 여부
- 패치 간 변경 항목과 충돌 보고서

### 12.2 경기 수집

- 지역, 큐, 패치 및 최대 경기 수 선택
- API 키 상태와 호출 제한 상태
- 진행률, 수집·중복·제외·실패 건수
- 취소와 안전한 재개

### 12.3 분석

- 패치, 지역, 티어, 큐 필터
- 기물, 시너지, 아이템 및 증강 검색
- 평균 순위, Top 4, 1위, 표본 수 및 신뢰구간
- 같은 로비의 두 관측 조합 간 상대 배치 우위율
- 모든 결과의 수집 기간과 데이터 출처
- `과거 관측 결과이며 전투 예측이나 플레이 권고가 아님`을 알리는 설명

## 13. 테스트 전략

- 소스 어댑터: 저장된 최소 픽스처로 필드 매핑과 스키마 변경 감지 테스트
- 병합기: 공식 우선, 보완 적용, 충돌 보고 테스트
- 정적 검증기: 중복 ID, 끊어진 참조, 누락 현지화 및 이미지 오류 테스트
- 익명화기: PUUID, 이름, 원본 Match ID 및 알려진 식별 필드 제거 테스트
- 집계기: 평균 순위, Top 4, 1위, 상대 배치 우위 및 중복 제거 테스트
- 통계: Wilson 신뢰구간과 최소 표본 차단 테스트
- 정책 필터: 금지 지표, 실시간 입력 및 추천 표현이 노출되지 않는지 테스트
- 저장소: 원본 경기 응답이 정상·오류 경로 모두에서 디스크와 로그에 기록되지 않는지 테스트
- 결정성: 동일 입력이 동일 정규화 JSON과 콘텐츠 해시를 생성하는지 테스트
- Editor 통합: 다운로드 승인, 취소, 재시도, 패치 활성화 흐름 테스트

네트워크에 의존하는 검증은 소수의 명시적 통합 테스트로 제한하고 기본 테스트는 저장된 창작·축약 픽스처를 사용한다.

## 14. 별도 전투 기술 연구 프로젝트

전투 기술 연구는 이 프로젝트의 코드, 데이터 및 에셋을 참조하지 않는 별도 Unity 프로젝트와 저장소에서 수행한다.

- 프로젝트와 제품 이름에 TFT 또는 Riot 상표를 사용하지 않는다.
- 기물, 특성, 아이템, 증강, 설명문 및 아이콘은 모두 창작한다.
- TFT의 데이터 파일이나 내부 ID를 입력으로 받지 않는다.
- 범용 이동, 타게팅, 피해, 회복, 상태 효과 및 이벤트 시스템만 연구한다.
- 두 프로젝트 사이에 공유 코드 패키지를 두지 않는다.
- 기술 개념이 유사하더라도 수치, 명칭, 표현 및 자산을 복사하지 않는다.

이 분리는 TFT 데이터 분석 결과가 전투 재현 기능으로 직접 연결되는 것을 방지하기 위한 제품 경계다.

## 15. 구현 순서

구현은 다음 순서로 진행한다.

1. 프로젝트 명칭과 폴더 구조를 데이터 분석 도구에 맞게 변경
2. 내부 정적 데이터 스키마와 창작 테스트 픽스처 정의
3. Riot Data Dragon 어댑터와 패치 매니페스트 구현
4. 정적 데이터 검증과 패치 비교 구현
5. 선택형 CommunityDragon 보완 어댑터 구현
6. `TFT Data Analyzer` Editor 창의 데이터 관리 화면 구현
7. Riot API 키 보안 입력과 Match API 수집기 구현
8. 즉시 익명화, 중복 제거 및 로컬 관측 저장소 구현
9. 집계기와 신뢰구간 계산 구현
10. 분석 화면과 정책 필터 구현
11. 전체 통합 검증과 외부 제공 전 정책 재검토

별도 전투 기술 연구 프로젝트는 이 분석 도구의 구현 범위에 포함하지 않으며 별도 설계와 계획을 거쳐 생성한다.
