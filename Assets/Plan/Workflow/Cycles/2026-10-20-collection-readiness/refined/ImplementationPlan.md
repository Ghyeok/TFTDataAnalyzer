# 경기 수집 전 준비 상태 안내 수정 계획

2026-10-20. 상태: 완료. 승인 범위 구현·코드 검수·QA·문서·PR15 병합 후 사용자 최종 승인 완료. 기준 main fa0df4df96bb1cc670c543f293fb4c39c5801959. 기존 네 탭과 수집 계약을 유지하는 작은 수정이다.

## 문제와 목표

사용자 화면에서는 활성 카탈로그가 표시돼도 하단 상태가 계속 “데이터 관리 탭에서 검증된 카탈로그를 선택해 주세요.”였다. CollectionViewModel의 초기 StatusText는 그 문구이며 SetCatalog/TrySetInput은 입력 유효성만, RefreshConfiguration은 설정 여부만 바꾸고 준비 안내를 갱신하지 않는다. 다음 행동을 알 수 있게 수집을 시작하기 전 Idle 상태의 안내를 실제 준비 조건과 맞춘다.

## 범위와 선택

- 기존 collection-status Label과 Changed/Render 경로를 사용한다. 새 창·탭·설정 저장·비밀값 입력창·새 네트워크 요청은 추가하지 않는다.
- 제품 수정은 Editor/UI/Collection/CollectionViewModel.cs 한 파일을 우선한다. 테스트는 기존 CollectionViewModelTests.cs와 필요할 때만 CollectionTabTests.cs를 보완한다.
- 순수 상태 갱신 helper를 ValidateLatestInput과 RefreshConfiguration 종료 시 호출한다. disposed/busy/Idle 이외 상태에서는 실행 결과·취소·오류·진행률 문구를 바꾸지 않는다. 기존 Notify 횟수는 늘리지 않는다.
- 안내 우선순위: 카탈로그 미선택 → 입력 무효 → 키·시드 둘 다 없음 → 키 없음 → 시드 없음 → 입력 조건 준비됨. 키/시드의 실제 값 대신 기존 bool만 사용한다. 준비됨은 설정 존재/입력 조건 확인이며 실제 API 키 유효성이나 서버 연결 성공을 뜻하지 않는다.
- 준비 문구 예: “API 키와 수집 대상 설정이 필요합니다. 환경 설정 후 ‘환경 설정 확인’을 눌러 주세요.” / “입력 조건이 갖춰졌습니다. ‘조건 확인 후 수집’을 눌러 주세요.” 터미널 결과는 보존한다.
- 종료 후 명시적으로 입력·카탈로그를 바꾸거나 환경 설정을 재확인해도 Idle로 자동 복귀시키지 않는다. 직전 실행/취소/오류 결과·오류 코드·진행률은 보존하고 기존 설정 여부 라벨과 CanStart만 현재 조건을 반영한다. 새 수집은 기존 StartAsync의 AwaitingApproval→Running 경로로 시작한다. 이번 수정의 준비 안내 대상은 최초 수집 전 Idle 상태다.
- 기본 CanStart, 수집 상한·지역/큐·티어 의미·실행 snapshot·사용자 승인·취소·중복/익명화·저장 정책은 변경하지 않는다. 자동 수집/환경 설정 변경/PUUID 조회/실제 개인 API 호출은 없다.
