# 기존 구현 검토 요약과 다음 범위

기획 조사 당시 기준 main fa0df4d(PR14). 당시 작업 트리는 닫힌 codex/startup-e2e 브랜치이며 사용자 DefaultVolumeProfile.asset와 이전 사이클 병합 체크포인트의 로컬 변경이 있다. 구현 전 새 codex/ 브랜치를 merged main에서 만들고 두 변경을 보존한다.

- Phase1: 공식/선택 보완 소스, 정규화·검증·불변 카탈로그·네 필드 identity·패치 비교가 구현됐다. 포함 카탈로그는 최신 패치 보장이 아니다.
- Phase2: 사용자가 제공한 seed만 상한 내 수집, 메모리 익명화·중복 제거·로컬 저장·집계·표본/정책 차단이 구현됐다. 실제 API 검증은 선택 항목이며 이번에도 실행하지 않는다.
- Phase3: 데이터 관리·경기 수집·분석·정책 안내, CSV, Player build gate, 시작 원본 버전 확인이 구현됐다. Task6 commit 체크는 실제 PR14 병합과 달리 아직 비어 있어 정리 대상이다.
- 현재 품질: 제품 전체620/619P/0F/호스트 링크1제외의 소스 트리와 merged main이 일치한다. 바깥 진단 경로 제외는 별도 실제 RED/GREEN을 확인했다. 코드 검수 및 검증과 실데이터 품질은 구분한다.
- 실제 한계: 기본 증강 분류 공급자가 없어 증강이 있는 조합의 일부 지표는 PolicyBlocked. 전체 보드 완전 일치 지문은 표본100을 모으기 어렵다. 이 두 항목은 기존 기획 검수에서도 후속 범위로 분리됐다. 임의 신뢰 분류·표본 기준 완화·임의 합산으로 우회하지 않는다.
- 새 작은 수정의 근거: 사용자 화면의 활성 카탈로그와 초기 상태 안내가 불일치한다. VM 생성 StatusText는 카탈로그 선택 안내이고 이후 준비 조건 변화가 그 값을 갱신하지 않는다. 기존 bool/유효 입력으로 Idle 안내만 갱신하면 별도 네트워크·키 저장·개인 식별자 취급 없이 혼동을 줄일 수 있다.
