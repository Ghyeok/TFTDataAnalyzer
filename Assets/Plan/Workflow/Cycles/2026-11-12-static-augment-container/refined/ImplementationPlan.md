# Riot 증강 메타데이터 중복으로 인한 가져오기 실패

상태: 기획 검토 중. 기준 main: 0eee6dfb6c284488c59cbd51e17822bafc27ef68.

## 확인된 사실
- 사용자가 요청한 원본 버전 16.22.1의 공식 증강 파일(ko_KR/en_US)에서 `augment-container` 안의 `name`과 `image`가 각각 8회 반복되고 일부 값이 다르다.
- 각 증강 파일의 `data`에는 760개 항목이 있고 중복 JSON 속성은 해당 두 경로뿐이었다. 다른 공식 기물·시너지·아이템 6개 문서에서도 중복 JSON 속성이 검출되지 않았다.
- `DataDragonAdapter.ReadRecords`는 전체 원본을 `StructuredStaticReader.ParseDocument`에 넘기고, 중복 속성을 거부해 data를 읽기 전에 `ddragon_invalid_static_data`를 반환한다. 해당 메타데이터는 현재 추출에 쓰이지 않는다.
- 전체 변환·검증·게시 성공은 아직 확인하지 않았으므로 추가 원인이 있을 수 있다. 기존 카탈로그를 변경하지 않는다.

## 제안과 완료 조건
1. 공식 Data Dragon 증강 문서의 최상위 `augment-container`만 값을 선택하지 않고 건너뛰되 JSON 전체의 문법과 종료를 검증한다. 속성명 중복 여부를 그 하위에 한해 예외로 다룬다. 최상위와 `data` 및 다른 메타데이터의 중복은 거부하며 나머지 문서와 공통 파서는 엄격하게 유지한다.
2. 건너뛴 값이나 원문을 출력하지 않는 구조화된 경고 코드·설명을 최근 가져오기 보고서에 표시한다. 알 수 없는 최상위 속성도 기존 파싱 동작을 유지하고 중복은 금지한다.
3. 비정상 종료·잘못된 구조·과도한 깊이·길이는 우회하지 않으며 기존 전송 및 JSON 처리의 제한을 확인해 구체적인 상한을 정한다. 기존 카탈로그, 출처·해시, 게시 원자성, 사용자 데이터는 보존한다.
4. 양 언어, 중복 값의 일치·불일치, 최상위 및 data 내부 중복, 잘못된 JSON·뒤에 붙은 데이터, 중첩과 길이 경계, 기존 다른 문서의 엄격 검증을 재현하는 테스트를 먼저 작성한다. 관련 테스트 후 공통 파싱·저장 영향 범위를 검토해 필요시 전체 테스트를 실행한다.
5. 별도 임시 저장 위치에서 실제 16.22.1 공식 자료를 대상으로 파싱과 검증을 확인한다. 추가 문제를 발견하면 임의로 다른 검증을 완화하지 않고 원인을 조사한다. 공식+보완 자료 프로필도 별도로 확인할 수 있을 때만 결과를 주장한다.

## 검토 상태
- Antigravity (agy 1.5.6, Gemini 4 Argon Medium): pass, 경고 표시와 상한, 기타 최상위 필드의 명시 필요. 입력 2,529바이트, 총 10,274 토큰. 실행 산출물: `AntigravityCollab/tasks/2026-11-12-static-container-planning/outputs/`.
- GPT: 명시적 예외 범위, 손상 data의 fail-closed, 경고 전달, 언어별 별도 검증 및 격리 저장 필요. 독립 기술 검토 진행 중.
- 실제 전체 자료 파싱, Unity 테스트, 제품 수정, QA: 미실행.

독립 기술 검토: 기존 담당자를 재사용해 검토했다. 정확한 루트 경로 예외·루트 및 data 중복 차단, 무시 구간을 포함한 문법/EOF 검증, 제한과 취소 경로, 경고의 보고서 전달을 확인해야 한다. `ReadRecords`의 동일 ID 덮어쓰기는 JSON 속성 중복과 별개인 기존 위험이다. 실제 16.22.1의 공식 8개 문서에서는 각 문서별 ID 충돌 0건으로 확인했다. 원본 760개 → 세트 필터 → 최종 항목을 비교하고, 충돌 처리의 동작 변경은 별도 범위 검토 후 결정한다. 경기 API 호출·실제 카탈로그 게시·기존 카탈로그 변경은 수행하지 않았다.
