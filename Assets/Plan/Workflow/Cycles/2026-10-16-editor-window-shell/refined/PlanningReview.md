# 통합 Editor 창 기획 검토

날짜: 2026-10-16
상태: 진행 중 — 기존 확정 설계의 Phase 3 Task 1 실행.

## 범위와 완료 조건

| 대상 | 완료·검수 조건 | 실행 증거 |
|---|---|---|
| 창 | `TFT Analyzer/Open Data Analyzer`에서 통합 창 열기 | 메뉴 실행·실제 창 확인 |
| 탭 | `data-tab`, `collection-tab`, `analysis-tab`, `about-tab` 중 하나만 표시 | 기본 선택·실제 버튼 이벤트 전환 EditMode |
| 재생성 | 선택 유지, 루트·footer·stylesheet 중복 방지 | CreateGUI 재호출·직렬화 복원 검증을 구분 |
| 고지 | `historical-data-disclaimer`가 콘텐츠 밖에 유지 | 모든 탭과 누락 화면 검증 |
| 누락 | UXML/USS 각각 누락되어도 오류 안내와 고지 표시 | 사용자 자산 이동 없이 부재 경로로 검증 |
| 회귀 | 기존 카탈로그·사용자 변경·정적 import 유지 | 보호 해시·diff·전체 EditMode |

기획 A는 제품·정책 경계를 검토했고 차단 모호성이 없다고 보고했다. 기획 B는 단일 EditorWindow, 직렬화된 선택 탭, 기존 InternalsVisibleTo 활용, 최소 로딩 분기와 실제 UI 이벤트 테스트를 권고했다. ViewModel·서비스·로더 인터페이스는 이번에 만들지 않는다.

## 판단

- 사용자 재개 요청을 이미 안내한 다음 작업과 연결해 기존 Task 1 실행 승인으로 취급한다. 새 제품 범위를 추가하는 기획으로 해석하지 않는다.
- 같은 객체의 CreateGUI 재호출은 재생성 검증이며 domain reload 전체 검증이라고 기록하지 않는다. 직렬화 복원을 별도로 검증할 수 있다.
- 네 탭에는 후속 기능임을 명확히 표시한다. 누르면 실행되지 않는 수집·내보내기 버튼은 만들지 않는다.
- 화면을 여는 동작으로 네트워크·키/seed 조회·관측 저장을 시작하지 않는다. 기존 Phase 1/2의 Explicit 실네트워크 확인은 이번에도 미실행이며 로컬 UI 착수의 필수 검증을 대체하지 않는다.
- 두 독립 검토가 합의한 구조를 따르며 새로운 패키지나 시각 자산은 필요 없다.
