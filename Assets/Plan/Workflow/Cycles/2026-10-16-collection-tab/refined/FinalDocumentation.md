# 경기 수집 탭 사용 안내

갱신일: 2026-10-18
상태: 기능 구현·실행 검증·독립 QA·문서 대조·통합 커밋 완료, PR 검수 및 사용자 완료 승인은 별도

1. `TFT Analyzer > Open Data Analyzer`를 열고 데이터 관리에서 검증된 카탈로그를 선택한다. 기존 schema1 공식 전용 카탈로그도 검증된 전체 식별자로 연결되며 원본을 변환하지 않는다.
2. 환경에 `RIOT_API_KEY`와 `RIOT_TFT_SEED_PUUIDS`를 구성한다. 수집 탭의 환경 설정 확인은 값 대신 설정 여부만 표시한다. 창 열기·탭 전환은 수집을 시작하지 않는다.
3. 플랫폼·큐·티어 기록 라벨·상세 시도 상한1–1,000을 지정한다. 티어는 실제 참가자 등급을 조회한 결과가 아니다. 제공된 seed만 조회하고 참가자를 새 seed로 탐색하지 않는다.
4. 조건 확인 후 수집을 누르고 전체 카탈로그 식별자·라우팅·큐·상한·seed 범위를 확인한다. 거절하면 요청하지 않는다. 실행 중 입력과 중복 시작은 막힌다.
5. 상세 시도·가져옴·저장·중복·필터 제외·실패·목록 페이지를 확인한다. 상한은 저장 성공 수가 아닌 상세 요청 시도 수이며, ID 탐색은 최대10페이지다. 표본이 작거나 중복·제외가 있으면 저장 수는 더 작을 수 있다.
6. 취소는 작업 종료까지 기다린다. 이미 저장된 익명 관측은 보존한다. 401/403은 설정을 확인하고 429는 표시된 UTC 이후 수동 재시도한다. 자동 재개하지 않는다. 창을 닫으면 취소를 요청하고 늦은 진행 알림을 차단한다.

수집 이후 집계 자동 갱신·분석 화면·CSV·정책 화면은 후속 작업이다. 활성 카탈로그 선택은 창 닫기/리로드 뒤 영속 복원하지 않는다. 키·seed·PUUID·원본 Match ID를 화면이나 로그에 기록하지 않는다.

최신 전체 EditMode는467/467이며 실제 포함 카탈로그와940px·500px 화면을 확인했다. 검증 창은 정상·통제된 실패 경로 모두 잔류0, 사용자 창·바깥 프레임을 보존했다. 실제 API 호출과 네이티브 확인창 클릭은 미실행이며 Console의 이전 Pipeline 통신 오류2건은 별도 제한으로 기록했다. 자세한 증거는 [개발 결과](DevelopmentReport.md)를 확인한다.

검증 도구는 [프로젝트 지침](../../../../../../docs/unity-editor-validation.md)을 따른다. PNG 검수는 도구의 성공 JSON과 별도이며, 과거 캡처 불일치가 다시 발생하면 화면 확인을 통과로 처리하지 않는다. 현재 Idle 안내가 선택을 다시 요청할 수 있는 문구 문제는 비차단 후속 항목이다.
