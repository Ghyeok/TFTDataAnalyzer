## 범위와 결정

- 데이터 관리에서 선택한 검증된 전체 카탈로그 식별자와 카탈로그를 연결한다. 예상 패치는 읽기 전용이다.
- 플랫폼, 큐, 기록용 티어 분류, 1–1,000건의 고유 상세 조회 시도 상한을 확인한 뒤 매 실행마다 사용자 확인을 받는다. 티어는 실제 참가자 등급을 조회·검증한 필터가 아니다.
- API 키와 사용자 제공 시작 계정은 설정 여부만 표시한다. 값·원본 응답·임의 예외 내용은 화면과 기록으로 전달하지 않는다.
- 기존 수집기·익명화·저장소를 재사용한다. 창 수명 동안 같은 클라이언트와 요청 제한 상태를 유지한다. 실제 Riot 네트워크 수집은 검증에 사용하지 않는다.
- 실행 전 카탈로그와 입력을 캡처한다. 입력·중복 시작은 확인/수집/취소 처리 중 차단한다. 취소 요청 후 실제 종료까지 busy를 유지하며 최종 요약과 저장 개수를 보존한다.
- 429는 기존 수집기가 중단한다. 재시도 가능 UTC와 수동 재시도를 안내한다. 자동 재개나 새 스케줄러를 추가하지 않는다.
- UI 재생성은 바인딩만 교체하고 VM을 유지한다. 닫기는 취소·관찰 해제를 수행한다. 이전 실행의 지연 진행 알림은 무시한다.
- 분석 표·집계 재생성·정책 설정·내보내기는 후속 Task 범위다. 기존 생성 카탈로그와 사용자 Volume 변경을 보존한다.

## 완료·검수 증거

경계값/입력/비밀값 비노출/확인 거절/캡처 불변성/중복 실행/취소/401·403·429/부분 실패/조회 한도/늦은 진행 알림을 fake로 검증한다. 실제 UI 이벤트로 입력 잠금·취소·재생성을 확인한다. fake transport를 통한 기존 수집기·익명 저장 통합을 확인하고 전체 EditMode 테스트, 컴파일·Console, 실제 창과 최소 크기, 보호 파일 해시를 대조한다.

## 독립 검토 통합

범위 검토와 기술 검토는 모두 위 구성을 권고했다. 설계의 “자동 재시도 시간”은 기존 backend가 반환하는 재시도 가능 시각으로 해석한다. Task 3에서 backend 동작을 확대하지 않는다. 입력과 활성 카탈로그의 실행 시점 snapshot을 고정하므로 다른 탭의 선택 변경이 승인된 실행에 영향을 주지 않는다.
