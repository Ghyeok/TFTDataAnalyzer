## 공통 결론

- **방향은 유지한다.** 실제 형태를 모르는 상태에서 2단계를 설계하지 않고, 형태 진단을 먼저 한다는 권장 순서에 두 검토 모두 반대하지 않았다.
- **진단만으로 B(정상 경로 확장)를 결정하지 않는다.** A는 공식 또는 동등한 근거가 없으면 C/D로 가야 한다고 했고, B는 같은 내용을 사전 판정 규칙으로 제시했다. 20경기 형태가 모두 같아도 관측되지 않은 형태가 있을 가능성의 95% 상한은 약 14%다.
- **1단계 설계는 다시 써야 한다.** 기존 수집 경로를 재사용하면 요청 상한과 중단 정책을 지킬 수 없고(자동 재전송 최대 4회, 5xx·404 뒤 계속 진행, 큐 필터 없음), 기존 저장소는 읽기만 해도 파일을 쓴다. 형태 서명에는 비ASCII 문자, 긴 hex·GUID, 긴 숫자 그룹을 통한 누출 경로가 있다.

## 사실 정정

- `game_version` 수용 조건: `Version ` 접두는 선택이고 숫자 그룹 길이는 1-5/1-5/1-10/1-10이며, 공백 뒤 주석은 개행만 없으면 허용한다. 카탈로그 비교는 앞 두 그룹으로 한다. 괄호·태그는 실패 원인이 아니다.
- 검사 순서상 증강 누락이 두 버전 검사보다 먼저 실패한다. 지난 진단의 버전 범주는 별도 판독으로 얻은 것이고, 정상 경로의 실패 코드는 첫 위반만 보여 준다.
- 정상 저장 조건에는 참가자 8명, 순위 1~8 중복 없음, 세트·큐 일치, 정적 ID 전부 카탈로그 내, 증강 16개 이하도 포함된다.
- 불완전 기록에는 두 버전 원값이 없지만 파생 의미 상태와 `catalogHash`가 저장되고, 비밀값 없이 계산한 경기 ID 해시도 저장된다. 기존 안내 문서는 이 해시를 "제한된 로컬 자료"로 다룬다.
- 조합 지문 v2에는 증강이 들어가지 않는다. 증강은 중복 무결성용 `BuildStrict` v1에만 남아 있다. 근거 조사 문서의 "지문에 증강 포함" 서술은 PR #29 이전 기준이다.

| A2 표본 규모 정량 분석 | 2단계 진입 조건으로 둔다. 1단계에 ID 없는 조합 다양성 집계(정확히 같은 조합의 빈도 분포)를 추가해 실측 근거를 얻는다. |

| A5 최초 5건과의 관계 | 경기 ID를 저장하지 않으므로 최초 5건과 같은 경기인지 대응할 수 없다고 명시한다. 1단계는 불완전 기록을 포함한 기존 저장소에 쓰지 않는다. |

| B2 요청 상한 | 전송 예산 래퍼와 중단 규칙으로 반영한다. |

| B4 서명 누출·판정 부족 | 유니코드 범주 치환, 긴 구간 접기, 판정용 추가 항목, 사전 판정 규칙으로 반영한다. |
| B5 객관적 완료 조건 | 합성 RED 테스트 (a)~(f)와 완료 조건으로 반영한다. |
| B6 2단계 계약 | 2단계 기획 진입 조건 목록으로 반영한다. |

## 사용자 결정이 필요한 사항

1. **1단계 실제 호출(필수)**: 합성 테스트·코드검수 통과 후 실제 Riot API를 1회 실행해도 되는지와 경기 수 N. 권장 N=20(목록 1회 + 상세 최대 20회, 다른 큐 경기도 포함).
2. **2단계 방향(진단 후 확정 가능)**: 패치를 확인할 수 없을 때 C(세트 단위 참고 통계)와 D(보류) 중 어느 쪽을 원하는지.
3. **증강 지표(진단 후 확정 가능)**: 증강 지표가 계속 막혀도 조합·아이템 통계만으로 사용할 가치가 있는지.
4. **표본 규모(인지 필요)**: 정확히 같은 조합 기준으로는 실제 데이터가 들어와도 비율 지표가 거의 표시되지 않을 수 있다. 조합의 점유율이 1%면 패치당 약 1,250경기, 0.3%면 약 4,200경기가 필요하다는 가정상 추정이다. 1단계의 조합 다양성 집계로 실측해 2단계에서 다룬다.

검토 지적이 계획을 크게 바꿨으므로, 사용자 결정 반영 후 수정안을 A·B에 한 번 더 확인받고 승인을 요청하는 것을 권장한다.

2026-11-16 사용자 답변: 1번은 N=20으로 허용하되, 만료된 API 키를 재설정했다고 사용자가 알린 뒤에 실행한다. 수정안은 A·B 재검토 후 승인받는다. 2~4번은 1단계 결과 후 다룬다.
