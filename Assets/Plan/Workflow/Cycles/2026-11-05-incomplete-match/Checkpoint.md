# 불완전 경기 보관 작업 체크포인트

2026-11-16 상태 갱신: 불완전 경기 보관 구현은 [PR #30](https://github.com/Ghyeok/TFTDataAnalyzer/pull/30)(head `5e436ea`)으로 2026-11-12 main에 병합됐다(커밋 `0eee6df`). 병합 head의 CodeRabbit 검사는 neutral, 미해결 검수 스레드는 0개였다. 이후 같은 브랜치의 병합 이력을 main에 연결하는 [PR #33](https://github.com/Ghyeok/TFTDataAnalyzer/pull/33)(head `281baa4`, CodeRabbit skipped)이 2026-11-13 병합됐다(병합 커밋 `1c310d9`). 아래 "구현 중"과 수동 화면 검증 실패 기록은 병합 전 상태다. 불완전 기록 상세의 실제 화면 검증 성공은 이 갱신에서 다시 확인하지 않았다.

2026-11-12 진행: 전용 후보 추출·저장·조회·선택 삭제와 수집 화면 연결을 구현 중이다. 사용자 기존 변경과 정상 관측 저장소를 보존한다. 실제 Riot API 호출은 없었다. 합성 수집 결과에서 기존 실패 분류와 별도 보관 결과를 나누고, 128건 상한과 직접 정리 안내를 추가했다. 안전한 재열람에는 선택된 게시 카탈로그의 identity·내용 검증이 필요하며, 미확인 카탈로그는 ID·이름·설명을 숨긴다. 보관 한도는 건당 256KiB·최대 128건으로 적용했다.

검증: Unity CLI beta.17, 관련 합성 테스트 115/115, 수집 서비스 39/39, 실제 전용 저장소 수집→재열람→삭제→재보관 합성 통합 1/1, 변경 후 수집 UI 13/13. 공통 파서·저장소 영향에 따라 전체 EditMode 1270건 중 1268 통과·0 실패·2 제외를 실행했으며, 이후 UI 상한 안내와 통합 테스트만 추가해 해당 관련 테스트를 다시 실행했다. 기존 Unity 창 9개 및 프레임 1개의 ID는 캡처 전후 동일했고 소유 창 잔류 0이다.

독립 재검수: 상한 안내와 전용 저장소 통합 테스트를 코드로 다시 검토했고 추가 지적은 없었다. 검수자는 테스트 CLI 출력 파일을 독립 확인하지 못했다.

미완료: 수동 화면 검증에서 초기 실행은 이전 결과 생성자 사용으로 실패했다. 원인을 수정한 뒤 검증 도구는 정리 성공을 보고했으나 두 PNG에 Unity가 아닌 다른 화면이 찍혀 실제 픽셀 검증은 실패했다. 잘못된 PNG는 삭제했고 동일 캡처 문제 반복 진단은 사용자 지시에 따라 중지했다. 불완전 기록 상세의 실제 시각 확인 및 PR은 미완료다. 합성 테스트와 창 정리 성공을 실제 화면 검증 성공으로 취급하지 않는다.

이후 사용자 요청으로 캡처를 1회 재실행했다. 940px·500px PNG에 Unity 수집 탭과 실패 집계가 찍힌 것을 직접 확인했고, 실행 전후 기존 창 9개·native 프레임 1개가 동일하며 소유 창 잔류는 0이었다. 합성 수집만 사용했고 실제 API 호출은 0이다. 이번 캡처는 접힌 불완전 기록 영역과 수집 요약까지만 보여 주므로, 기록 상세가 펼쳐진 화면의 실제 픽셀 검증을 대신하지 않는다. 이전 캡처가 다른 앱을 찍은 근본 원인이 해결됐다고 단정하지 않는다.

이후 상세 검증: 사용자가 요청한 합성 불완전 기록을 실제 상세 렌더러로 표시하여 940px·500px 캡처를 확인했다. 미검증·빈 배열·누락과 참고 카탈로그 안내가 보인다. 별도 기록의 실제 목록 선택은 기존 UI 테스트와 전용 저장소 통합 테스트에서 확인했고, 캡처 자체는 메모리 합성 기록을 상세 렌더러에 직접 전달했다. 기존 창 9개·프레임 1개가 유지됐고 소유 창 잔류 0, 실제 API 호출 0이다.

상태: 사용자가 2026-11-10 기존 구현 계획을 확인한 뒤 3번 작업 진행을 요청해 개발을 시작했다. 기획 기준 main ba50db8ad5ef8dc6ef58153cee57da0f8555588c, 개발 기준 main fd900fcf322949a0358d4b4984e2b3cbf6f9ba9f, 브랜치 codex/incomplete-match-records. 기존 기록 아래의 당시 승인·PR 상태는 이력이다.

현재 코드 재검토: 최근 정적 카탈로그와 조합 집계 병합으로 기존 보관 계획에 직접 충돌하는 변경은 발견되지 않았다. 기존 엄격 DTO 파서는 일부 형식 오류에서 즉시 중단하므로 예외 이후 같은 스트림을 다시 읽지 않고 단일 응답에서 후보와 전체 구문 검증을 수행해야 한다. 미지원·미확인 버전은 의미 미검증, 새 보관소는 정상 관측·인덱스·집계·CSV와 분리한다. 8MiB는 현재 파싱 단계 상한이며 전송 단계 메모리 상한을 보장하지 않는다. 최초 합성 전용 모델 존재 테스트는 미구현 상태에서 예상대로 실패했다. Unity CLI는 사용자 승인 후 beta.17로 업데이트했다. 실제 경기 API는 호출하지 않았다.

기존 정적 카탈로그 탐색·비교·현지화 저장은 이미 구현되어 있다. PR25는 CodeRabbit 최신 3f4f3c6 성공·주석 검사100%·미해결0·EditMode 1018개 중1016통과/0실패/2제외를 확인해 main ba50db8로 병합됐다. 실제 경기 정상 저장 성공이나 최초 5건 각각의 원인은 여전히 미확인이다.

동일 비식별 기획 입력은 `AntigravityCollab/tasks/2026-11-05-incomplete-match-planning/inputs/`의 scope.md와 technical-context.md로 고정했다. 기획 B는 조건부 적합이며 `PlanningDraft.md`에 핵심을 반영했다. 기획 A 외부 전송은 최초 자동 승인 검토가 거절했으나 사용자 명시 승인 후 성공했고 revise를 반환했다. 제품 코드 변경·실제 경기 API 재호출·기존 카탈로그/관측 변경은 없다. 사용자 기존 변경과 Chrome·Unity 창을 보존하며 키 문서와 원본 경기는 읽지 않는다.

2026-11-06 갱신: Antigravity A가 통합안을 재검토해 사용자 확인 없는 자동 삭제와 중복·재보관 경로에 대해 revise를 반환했다. 사용자께서는 자동 삭제 없이 직접 정리하고 128건 도달 시 새 별도 보관을 중단하는 방향을 선택했다. [Riot 공개 자료 조사](RiotSourceReview-2026-11-06.md)는 완료했고 실제 경기 API 재호출과 외부 이슈 댓글은 없다.
