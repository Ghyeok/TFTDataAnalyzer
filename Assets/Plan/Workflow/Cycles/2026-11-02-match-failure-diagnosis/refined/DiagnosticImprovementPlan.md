# 경기 수집 실패 원인 안내 개선 제안

상태: 초안 — 사용자 승인 전 제품 수정 없음

## 문제와 한계

실제 수집에서 상세 5건을 가져왔지만 실패 5건만 표시되어, 사용자가 API 인증 실패·경기 입력 검증 실패·미지원 데이터 버전·저장 실패를 구분하기 어렵다. 제한 단일 진단에서는 set/queue 일치, game_version 패턴 불일치, data_version 1~5 외, 참가자 증강 속성 누락을 확인했다. 최초 5건 개별 원인과 진단 간 동일성은 미확인이다. Riot의 공개 안내만으로 이번 데이터 버전 및 증강 누락의 의미를 입증하지 못했으므로 정상 데이터로 변환·저장하지 않는다.

## 제안 범위

수집 실행의 기존 실패 처리 지점에서 안전하게 이미 식별된 고정 오류 범주만 집계해 수집 화면에 안내한다. 예: 경기 입력 형식 검증 실패, 명시적으로 식별된 미지원 data_version, 저장/처리 실패. 범주를 확인할 수 없는 실패는 추정하지 않고 일반 실패로 유지한다. 화면의 합계·취소·중복·필터·429 동작 및 기존 통계 차단과 데이터 저장 판정은 바꾸지 않는다. 원문/필드 값/예외 텍스트/ID/키/URL을 화면·로그·저장소에 노출하지 않는다. 잘못된 data_version과 누락된 증강은 계속 차단한다. 과거 실행의 원인을 소급 복원하지 않는다.

현재 DTO 파싱은 data_version 판정 전에 실패할 수 있다. 단순히 기존 error.Code를 전달하는 구현은 누락과 미지원 버전이 동시에 있는 사례를 구분하지 못한다. 실제로 구분 가능한 범주는 엄격 JSON 검증·파서 제어 흐름을 근거로 정확히 정의하고, 보장할 수 없는 구분은 사용자에게 보여 주지 않는다. 정확한 원인을 얻기 위한 재파싱·원본 버퍼링·JSON 경로 표시를 무심코 추가하지 않는다. 기획 검토에서 안전하게 구분 불가라면 해당 범주를 일반 입력 오류로 묶는다.

## 예상 변경과 검증

- MatchCollectionService·MatchCollectionSummary·CollectionProgressViewModel·CollectionViewModel/Tab의 고정 범주 전달 및 안내. 실제로 안전하게 구분 가능한 범위에 맞춰 상세 계약을 개발 전에 확정한다.
- 합성 정상/형식 오류/미지원 버전/저장 오류·취소/401/403/429·중복/카탈로그 불일치와 표기 확인, sentinel 개인정보/오류 메시지/URL 비노출, 기존 카탈로그·관측 불변 및 분석 정책 회귀.
- 독립 코드검수·QA, 제품 UI 변경 시 검증 전후 기존 창·프레임·포커스 보존과 소유 창 정리, 사용자 승인된 경우만 실데이터 확인, 문서·PR.

이 제안은 오류 설명을 개선할 뿐 실제 경기의 수집·저장 성공을 보장하지 않는다. 실제 신규 응답 형식 수용은 공식 계약과 의미를 확인한 별도 수정 계획이 필요하다. 기획 A/B 검토 및 사용자 명시 승인 전 구현하지 않는다.
