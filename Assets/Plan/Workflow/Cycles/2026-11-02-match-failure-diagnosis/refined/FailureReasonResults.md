# 경기 수집 실패 이유 표시 결과

작성일: 2026-11-05

상태: 승인 범위 구현·회귀·독립 코드검수·QA·합성 화면 검증 완료. PR 미생성, 병합 및 사용자 최종 승인 전.

## 변경과 사용법

경기 수집 탭의 실패 건수 아래에서 이번 수집 중 확인한 실패 이유를 읽을 수 있다. 지원하지 않는 데이터 버전, 게임 버전 확인 불가, 증강 정보 확인 실패, 기타 경기 형식 오류, API 오류, 저장·처리 오류를 구분한다. 경기 상세 외 목록 요청과 최상위 처리 실패도 포함하므로 건수의 의미는 실패 이벤트 수다. 이벤트마다 확인한 이유 하나만 더하고 여섯 범주의 합계를 기존 Failed와 일치시킨다.

파서는 기존 공개 Code를 유지하고 별도의 고정 ReasonCode로 세부 이유를 전달한다. DTO의 다른 필수값 검사가 먼저 실패하면 아직 도달하지 않은 버전 원인을 추측하지 않는다. 증강 필드의 누락·null·배열이 아닌 형식은 구분하지만 화면에서는 증강 정보 확인 실패로 합산한다. 실제 빈 배열은 기존대로 허용하고 안전하게 특정하지 못한 잘못된 원소는 일반 경기 형식 오류로 남긴다. 엄격 JSON 구문·자료형·중복·크기 제한과 경기 수용·거절 조건은 유지한다.

카탈로그 불일치, 큐 불일치와 정적 ID 격리는 기존 필터 결과다. 격리 보고서 저장 실패는 별도 상태로 남긴다. 취소나 예외가 발생해도 이미 보고된 분류와 저장 결과를 보존하며 다음 실행을 시작하면 새 집계로 초기화한다. 이전 실행의 늦은 콜백은 새 결과를 덮어쓰지 않는다. 화면은 먼저 확인한 이유만 보여 주며 다른 미확인 원인이 있을 수 있음을 함께 안내한다.

파서 RED에서는 59건 중 기존 54건이 통과하고 ReasonCode 부재로 신설 5건이 예상대로 실패했다. 수집 RED는 36건 중 33통과·3실패, 이후 FailureReason 필터는 서비스 1건과 UI 4건이 예상대로 실패한 뒤 5/5 GREEN을 확인했다. 추가 보강 후 위 대상 및 전체 회귀를 실행했다. RED에서 실패한 범위와 전체 실행 건수를 구분한다.

합성 입력으로 정상·누락·null·잘못된 타입/원소·중복·손상·크기/배열 제한·복수 오류를 확인했다. 목록/상세 API 오류, 저장 및 스트림 정리 오류, 범주 합계, 관측 보존, 취소, 다음 실행 초기화, 예외 fallback, 늦은 콜백, 범주별 UI 표시와 비밀 sentinel 미노출도 검증했다. 실제 API는 사용하지 않았다. 컴파일 및 테스트 수치는 root가 확인한 이 세션의 CLI 출력에 근거한다. 별도 컴파일·테스트 결과 파일은 저장하지 않았다.

실화면 도구는 [PowerShell 진입점](../../../../../../AgentScripts/Invoke-TftAnalyzerVisualValidation.ps1)의 `-FailureReasons`를 사용한다. 기존 `-QuarantineReport`의 요약 생성 인자도 갱신했다. 두 실행 모두 기존 EditorWindow 9개와 native ContainerWindow 1개 및 원래 포커스를 보존했다. 소유 창 잔류와 추가·누락 프레임은 각각 0개다. 화면 상태와 창 정리, 실제 PNG 확인을 각각 확인했다.

로컬 실행 증거는 `Library/TftAnalyzerValidation/collection-failure-reasons-visual-final.json`, `collection-window-940-failure-reasons.png`, `collection-window-500-failure-reasons.png` 및 `collection-quarantine-visual-final.json`이다. Library는 Git 제외 경로이므로 파일이 계속 보존된다고 보장하지 않는다. 실제 JSON의 정상 종료만으로 픽셀 검수를 대신하지 않았으며 실패 이유 두 이미지는 root가 직접 확인했다.

## 범위와 남은 일

원래 실패 5건을 소급 분류하지 않았고 실제 경기 저장 성공을 검증하지 않았다. 원본 경기 응답, API 키, PUUID, 경기 ID, 원문 값, 예외 메시지나 JSON 경로를 새 진단 자료로 저장하거나 표시하지 않는다. 사용자 변경과 기존 카탈로그를 수정하는 기능은 추가하지 않았다. 불완전 경기 익명 보관, 빈 값/알 수 없음 모델, 참고용 카탈로그 연결 및 통계 완화는 이번 구현 범위가 아니다.

PR 생성, 최신 head의 외부 검수·CI 확인, 병합 및 사용자 최종 승인이 남아 있다. 실제 모델·추론과 작업별 사용량·시간은 문서 담당이 독립 확인하지 못했으므로 미확인으로 남긴다. 구현 담당을 문서 담당으로 재사용했고 하위 위임은 하지 않았다.
