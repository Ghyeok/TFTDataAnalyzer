# 실제 경기 실패 진단·수정 계획

상태: 진행 중

목표: 실제 경기의 익명화 입력 실패 원인을 안전하게 규명하고, 확인된 원인만 수정한 뒤 테스트·독립 검수·QA 및 PR을 진행한다. 기준 main 6a6f787. 별도 실제 사용자 최종 승인은 유지한다.

## 현재 증거와 미확인

사용자 수집: 상세 5·가져옴 5·저장 0·필터 제외 0·실패 5. 키 교체 후 Unity 프로세스와 사용자 환경 변수의 값 일치를 값 노출 없이 확인했다. 이전 단일 경기 진단은 invalid_match_payload, 후속 제한 진단은 각 요청 시점의 최신 경기 한 건에서 참가자 중 augments가 배열이 아닌 경우가 있었고 data_version은 문자열이나 1·2가 아니었다. 정확한 값과 배열 부재·null·타입, 경기 모드·세트·버전은 확인하지 않았다. 진단 요청들이 같은 경기를 조회했는지는 확인하지 않았으며 어느 한 건의 결과도 원래 5건 전체에 적용하지 않는다.

MatchAnonymizer는 필수 DTO 전체를 먼저 읽고 오류를 하나의 코드로 합친다. 경기 세트·릴리스 비교는 그 다음이므로 구문/DTO 오류가 먼저 나면 카탈로그 불일치를 판정하지 못한다. 현재 수집 목록의 카탈로그는 18.2/16.18.1이며 경기와 일치하는지는 미확인이다. 현시점에는 자료 누락을 빈 배열로 처리하거나 미지원 data_version을 허용하지 않는다.

## 안전한 단계별 계획

1. [x] 기획 A/B가 동일한 동결 입력을 검토했다. 둘 다 revise였으며 요청 범위·출력 통제·미지원 자료의 성급한 허용 금지와 진단/수정 단계 분리를 아래에 통합했다. 재검토 pass로 주장하지 않는다.
2. [x] 로컬 합성 자료로 독립 진단 도구를 검증한다. 출력은 다음 고정 범주와 실행 결과만 허용한다: 단계(ok|configuration|api|parse|cancelled|internal), 세트와 릴리스(카탈로그 일치|불일치|누락|타입오류|미확인), data_version(1|2|기타|누락|타입오류), augments(전체 배열|누락 존재|null 존재|비배열 존재|미확인), 모드(사전 허용 목록과 일치|불일치|누락|타입오류|미확인). 값 자체·개수·임의 이름을 포함하지 않는다. 모든 자료 검증은 전체 응답의 크기·구문·중복·타입 검사를 우회한 적합성 판정이 아니며 진단 정보일 뿐이다. 키·PUUID·Match ID·원본 응답·임의 필드명/경로/값·예외 메시지·URL·원본 크기를 출력/로그/임시파일에 쓰지 않는다. 정상·손상·누락·null·잘못된 타입·중복 필드·크기 상한·취소·예외 시 누출 방지와 스트림 정리를 시험한다. 임의 자료로 안전을 먼저 확인하기 전 실제 호출은 하지 않는다.
3. [x] 실제 진단은 사용자의 허용된 seed 중 첫 1개만, 목록 1회와 상세 최대 1회로 제한한다. 응답은 메모리에만 두고 익명 관측을 저장하지 않으며 자동 재시도하지 않는다. 최초 인증/접근/호출제한(401/403/429), 전송·취소·출력 통제 실패, 이전과 동일한 정보만 나와 원인을 더 구분하지 못하는 경우 즉시 중단해 알린다. 진단 결과는 고정 범주만 보존하고 원래 5건의 개별 원인으로 확대하지 않는다.
4. [ ] 실제 원인과 공식 계약을 대조해 수정안을 확정한다. 미지원 경기의 조기 분류는 가설이며, 구문·중복·크기·타입 검증 및 fail-closed를 우회하는 방식으로 구현하지 않는다. 근거 없이 증강 null/누락을 빈 배열로 변환하거나 임의 data_version을 허용하지 않는다. 기획 A/B와 사용자 승인을 받은 범위에서만 변경한다.
5. [ ] 합성 실패 테스트 → 최소 수정 → 관련 테스트와 회귀, 독립 코드검수·QA, 사용자 데이터·창 보존을 검증한다. 실제 대상 경기의 저장 성공은 별도 실행 증거가 있을 때만 주장한다. 문서화 후 PR을 만든다. PR 최종 통합은 별도 조건에 따른다.

원본 경기 응답과 비밀은 협업 폴더에도 저장하지 않는다. Unity 창을 새로 열어 검증할 때는 프로젝트의 소유 창 절차를 따른다. 사용자가 합성 진단 제작과 위의 단일 제한 진단을 승인했다. 실제 원인에 따른 제품 수정은 구체적인 수정안을 별도 승인받는다.

## 승인된 1건 진단 결과

합성 진단 6건 및 확장16건, 정리 검수8건, 합성 전송16건 통과. 독립 검수에서 상세 스트림 정리 실패 누락을 발견해 실제 RED 후 수정·GREEN했다. 전송은 목록/상세 각 최대 1회, 401/403/429/500·취소·예외에서 재시도 금지를 가짜 전송으로 검증했다. 도구는 키·원문·ID·URL을 반환하지 않는다. 테스트 도구의 수신 크기 상한은 다운로드가 끝난 뒤 파싱 시 적용되며 네트워크 수신 메모리 상한은 검증하지 않았다. 실제 요청은 목록 최대 1회와 상세 1회를 사용했다.

진단 결과 Stage=ok(진단 구문 분석 완료), Set=match, Release=type_error, Version=other, Augments=missing, Mode=unverified다. 이 한 경기에서 참가자 중 증강 필드 누락은 현재 Required.Always와 양립하지 않으므로 파서가 그 지점에 도달하면 오류가 발생한다. 다만 다른 필드가 먼저 실패할 수 있어 최초 예외 지점을 특정하지 못했고, 오류 코드 하나가 원래 5건 전체에 적용된다고 단정하지 않는다. Release=type_error는 문자열이 아니거나 형식이 맞지 않는 경우를 합치며 구분하지 못했다. Version=other는 1·2가 아니라는 뜻이며 구체 값은 확인하지 않았다. 진단 완료는 기존 익명화 승인·저장 성공을 뜻하지 않는다.

현재까지 확인된 공식 TFT 설명은 과거 data_version 1·2 도입 이력이며 이번 other의 의미나 증강 누락의 안전한 해석을 보증하지 않는다. 추가 공식 근거 없이는 해당 실데이터를 정상 관측으로 저장하는 수정은 정당화하지 못한다. 다음 작업 후보는 미지원 데이터 버전과 자료 누락을 비식별 고정 범주로 표시하는 진단 개선이며, 실제 수집 성공을 보장하거나 잘못된 입력을 허용하지 않는다. 사용자 승인 범위의 원인 조사와 수정/PR은 아직 미완료다.

## 추가 진단 후보 — 별도 승인 전 실행 금지

기존 단일 조회 승인 한도를 모두 사용했다. 후속 후보는 같은 안전 조건·seed 1개·목록 최대 1회·상세 최대 1회·저장 및 자동 재시도 없음으로, data_version을 1/2/3/4/5/기타/누락/자료형 오류, game_version을 패턴 불일치/자료형 오류, queue를 1100 일치 여부로 구분하는 것이다. 이전 경기와 동일한지는 확인할 수 없고, 공식 의미나 원래 5건의 원인을 단정할 수 없다.

대안은 제품 코드가 아닌 Library/TftAnalyzerValidation/ki003/AlternativeIntegratedProbeRunner.cs에 준비했다. 합성 분류·전송 횟수·비밀 sentinel/URL 출력 방지·중복/크기/취소/정리 테스트와 독립 정적 검수를 통과했다. 데이터 버전 1·2가 other로 합쳐지는 대안의 오류를 합성 RED→GREEN으로 바로잡았다. 8MiB는 수신 후 파싱 상한이며 실제 전송 메모리 상한·Unity 로그는 미검증이다. 기존 승인에 없는 실제 호출이므로 별도 승인 전 실행하지 않는다.

## 별도 승인한 추가 한 건 진단 결과

사용자가 목록 최대 1회·상세 최대 1회, data_version 1~5/other, game_version 패턴/자료형, queue 1100 일치 여부의 추가 고정 범주 진단을 승인했다. SHA 1933cb0e939d5d91f6efcc00b94b5bb9bc7a7452886d7b8cc2fbfc958a6fa098의 합성 검수 완료 러너를 사용했다. 결과 Stage=ok, Set=match, Release=pattern_mismatch, Version=other, Augments=missing, Mode=unverified, Queue=match. 즉 이 경기의 게임 버전은 문자열이나 기존 숫자형 패턴에 맞지 않고 data_version은 1~5가 아니다. 진단 Stage=ok는 파싱 완료이지 익명화 수용·저장 성공을 뜻하지 않는다. 최초 5건 및 이전 진단과 경기 동일성은 확인하지 않았다. 키/PUUID/Match ID/원본 응답/원문 값은 출력·저장하지 않았다. 추가 실제 호출은 하지 않는다.
