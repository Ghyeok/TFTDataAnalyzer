# 불완전 경기 데이터의 실제 저장 지원 검토 초안

상태: 방향 확정, 상세 설계·구현 전. 2026-11-05 사용자는 읽을 수 있는 정보만 익명화하여 별도로 보관하고, 실제 빈 값과 알 수 없음을 구분하며, 추가 확인 필요 상태와 참고용 카탈로그를 표시하는 방향을 확정했다. 패치 미확인 기록은 확정 패치별 통계에 합치지 않는다. 세부 계약·구현 승인은 별도이며 지금은 실패 사유 안내를 먼저 진행한다. 세부 원본·식별자 없이 관찰된 한 경기의 조건과 저장·정책 코드를 바탕으로 한다.

## 해결해야 할 문제

실제 조회한 한 경기에서 참가자 증강 항목의 부재, 확인되지 않은 data_version, 숫자 릴리스로 해석되지 않는 game_version이 확인됐다. 최초 5건 각각의 원인과 같은 경기인지는 확인되지 않았다. 세트18/큐1100의 공개 제보는 이런 유형의 존재를 뒷받침하지만 우리 응답의 정확한 값이나 Riot의 의미·정책을 인증하지 않는다. [근거 조사](SourceResearch.md).

## 선택지

1. 현행 검증을 유지하고 실패 이유만 비식별로 안내한다. 기존 데이터·지표의 신뢰성을 유지하지만 실제 불완전 경기의 저장·분석을 지원하지 않는다.
2. 패치와 증강의 출처 신뢰성을 명시한 새로운 익명 관측 형식과 별도의 격리 상태를 설계한다. 패치가 확인되기 전에는 기존 catalog scope·조합 지문·집계/CSV와 완전히 분리하고, 증강 미제공은 실제 빈 배열과 다르게 표시하며 불확실한 비율·상대 지표를 fail-closed한다. 나중에 신뢰 가능한 버전 근거가 없으면 정상 분석으로 승격하지 않는다. 식별 정보 및 원문을 저장하지 않고 중복·저장 실패·취소·손상 복구·용량 제한·동일 경기 재처리를 별도 설계해야 한다. 이 선택지만으로 패치 식별 문제나 수집 성공이 자동 해결되는 것은 아니다.
3. Riot의 공식 응답 계약이나 신뢰 가능한 버전 식별 수단을 확보할 때까지 정상 저장 지원을 보류한다. 데이터 의미와 출처는 보존하지만 외부 자료가 해결되기 전 정상 저장 성공을 보장할 수 없다. 사용자 요청에 따라 외부 댓글은 게시하지 않았다.

## 검토가 필요한 구체 계약

- data_version 허용 조건 및 각 버전의 필수 필드·타입·시맨틱을 공식 또는 동등한 신뢰 근거로 규정한다. `other`를 무조건 수용하지 않는다.
- 게임 릴리스의 검증 가능한 출처·정확도·세트/카탈로그 연결 기준을 정한다. 세트와 날짜로 임의 패치를 추정하지 않는다.
- 증강 availability를 알려진 빈 목록/제공된 값/미제공으로 분리하고, 모르는 증강이 평균·Top4/1위·상대 지표·CSV에서 어떤 제한을 갖는지 사용자 가치와 정책 기준으로 확정한다.
- 새 observation 및 fingerprint 스키마, 기존 schema1 불변 유지, aggregate schema2 캐시 무효화/재구성, unknown-ID/Legend/n100·파일 및 개인정보 보호를 설계한다.
- 격리 여부와 최종 저장 위치, 사용자 동의, 보존 기간·상한, 원자적 쓰기·복구·중복 처리, 파일/경로 재파싱 방어, 이전 데이터와 충돌을 명시한다.
- 모든 경로는 먼저 합성 RED/GREEN과 정책·CSV·복구·취소·개인정보 누출 회귀, 코드검수 및 QA를 수행한다. 원래 5건과 이후 1건의 재현 관계는 별도로 검증한다.

A/B 기획 검토와 사용자 명시 승인 전 구현하지 않는다. 이 초안은 데이터 지원을 완료했다고 판단하지 않는다.
