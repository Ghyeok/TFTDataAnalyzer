# 경기 수집 실패 이유 표시 계획

상태: 사용자 요청 범위 승인 후 구현·대상 및 전체 회귀·독립 코드검수·QA·합성 화면 검증 완료. PR은 아직 생성하지 않았고 사용자 최종 승인은 남아 있다. 사용자 2026-11-05 요청에 따라 새 수집에서 확인한 실패 이유를 구분해 안내한다. 미확인 원인을 확정하거나 원래 5건을 소급 분류하지 않는다. 실제 결과와 증거의 한계는 [실패 이유 표시 결과](FailureReasonResults.md)에 기록했다.

## 범위

- 새 수집 중 확인한 실패만 제한된 고정 범주와 건수로 화면에 표시한다. 후보: 지원하지 않는 데이터 버전, 게임 버전 확인 불가, 증강 정보 확인 실패, 기타 경기 형식 오류, API 오류, 저장·처리 오류. 확실히 판별하지 못한 경우 일반 분류를 사용한다. UI는 이후에 확인되지 않은 다른 원인이 없다는 뜻으로 표현하지 않는다.
- 현재 실패 수는 경기 상세뿐 아니라 목록 요청 및 최상위 처리 오류도 포함한다. 범주별 실패 이벤트가 중복 집계되지 않도록 설계하고 기존 실패·필터·저장 결과를 바꾸지 않는다. 취소·새 수집·이전 결과 보존의 기존 계약을 유지한다.
- API 키, PUUID, 경기 ID, 원본 응답, 원문 필드값, 예외 메시지나 JSON 경로를 표시하거나 저장하지 않는다. 실제 API 호출, 미지원 경기의 수용 및 저장, 통계 완화는 범위 밖이다.
- 별도 후속 방향: 확인된 경기 정보를 익명으로 격리 보관하고 실제 빈 값과 알 수 없음을 구분하며 추가 확인 필요 및 참고용 카탈로그를 표시한다. 이 기능 자체는 이번에 구현하지 않는다.

## 검토할 기술 계약

현재 DTO의 필수 항목 누락은 다른 검사보다 앞서 실패할 수 있다. 예외 메시지 해석에 의존하지 않고 명시적으로 확정할 수 있는 분류만 도입한다. 조기 실패로 진단하지 못한 게임 버전·데이터 버전은 추측하지 않는다. 기존의 엄격한 구문·크기·중복 필드·자료형·필수값 검증과 데이터 수용 조건은 보존한다. 누락 및 잘못된 형식의 증강을 구분할 수 있는 안전한 신호를 검증하지 못하면 일반 경기 형식 오류로 처리한다.

## 검증 조건

합성 정상/누락/null/잘못된 타입/중복/손상/크기 제한, 여러 문제가 있는 경우, 취소·API 및 처리 실패, 범주별 집계와 다음 실행 초기화, UI 문구 및 기존 결과 보존, 식별 정보와 예외 메시지 누출 방지를 검증한다. 기존 수집·익명화 회귀를 실행하고 독립 검수·QA를 수행한다. 실제 경기 성공은 별도 실행 증거 없이 주장하지 않는다.
