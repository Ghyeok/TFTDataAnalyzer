# 구조화 정적 데이터 사용법과 결과

상태: 진행 중

진행 결과: 구현·독립 코드검수·QA 통과, PR 통합 준비. 사용자 최종 결과 승인은 별도다.

기물 능력치·스킬 원본 수치, 시너지 원본 구간, 아이템 unique와 아직 의미를 해석하지 않은 확장 자료를 값별 출처와 함께 새 schema4 카탈로그에 보존한다. 실제 양 어댑터→공식 우선 병합→검증→아이콘→불변 게시→loader→탐색·패치 차이까지 연결했다. 자료가 없으면 값이나 규칙을 추정하지 않는다.

## 확인 방법

1. 데이터 관리에서 검증된 카탈로그를 선택하고 ‘카탈로그 내용 탐색’을 펼친다.
2. 기물·시너지·아이템·증강을 검색해 항목을 선택한다.
3. ‘구조화 자료’를 펼치면 값과 공식/보완 URL·SHA를20행씩 읽는다. ‘이전 자료/다음 자료’로 나머지 항목에 접근한다.
4. ‘원본 확장 자료(의미 미확인)’의 ‘원문 보기’를 누르면 읽기 전용 JSON을4096자씩 넘긴다. 원문은 실행·규칙·증강 통계 허용에 사용하지 않는다.

null은 ‘자료 없음’,0은0, false는‘아니요’로 구분한다. 스킬 배열은 원본 슬롯이며 성급표로 인증하지 않는다. 시너지 null 경계·스타일 코드를 임의의 활성 조건으로 계산하지 않고 unique를 장착 개수 제한으로 해석하지 않는다. 검색/항목/카탈로그를 바꾸면 상세 페이지를 초기화한다.

기존 schema1/2/3의 파일·해시·문서 출처·기존 값별 출처는 자동 변환하지 않는다. 같은 identity의 기존 의미가 같으면 실제 구 형식 팩을 재사용하고 구조화 자료 미저장 안내를 표시한다. 새 원본/기존 값/기존 출처가 달라졌으면 충돌로 거절한다. 새 schema4도 같은 identity로 다른 내용을 덮어쓰지 않는다.

## 검증과 제한

최신 EditMode939개 중937통과·실패0·Windows symlink 권한2제외, 관련113건/UI227건/게시16건을 확인했다. 원본 serializer로 생성한 schema3 골든 SHA와 동결227파일은 그대로다. 정상·표시 전후 예외에서 기존9창/native1·포커스 보존과 소유창0, 보호1389파일 변경·추가0을 확인했다. 940/500px8PNG는 실제 열어 확인했으며 작은 창의 하단은 스크롤이 필요하다. [QA와 환경 한계](QAReport.md)를 함께 확인한다.

공식과 보완 각각 허용된 확장이라도 병합 합계가 레코드별 UTF8 64KiB를 넘으면 고정 오류를 보고하고 게시하지 않는다. 깊이16·중복 키·손상 타입·비유한 수를 거절한다. 날짜처럼 보이는 원문 문자열도 자동 변환하지 않는다. 알려진 구조의 미선택 언어 손상도 오류다.

실제 다운로드/Match API·실제 증강 분류 등록·실제 n100 사용성은 검증하지 않았다. 등록0 및 미분류 증강 차단은 유지한다. 성급/장착 의미의 미공급, KI-001 간헐 가져오기 위험과 사용자 최종 확인도 남아 있다. 이전 Editor Console1오류는 원인 미확인이고 새 Editor0/0으로 해결을 주장하지 않는다. Chrome/사용자Volume/키문서/기존카탈로그·관측은 보존했다. 새 에이전트·Hermes 예약·외부 배포는 추가하지 않았다.

실제 GPT 모델/추론/사용량은 미확인이다. 기획 A의 확인 가능한1회 실행은 agy1.4.7/gemini-4-argon-medium/effortmedium/25190tokens/144.241초이며 thinking을 다시 합산하지 않는다. 제품/테스트 실행 시간과 전체 대화 누적 사용량을 이 값으로 대체하지 않는다.
