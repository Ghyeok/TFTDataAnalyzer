# 경기 종료 조합 기준과 조건별 재집계 계획

상태: 사용자가 구현을 승인했으며 개발 중. 정적 변경 요약 PR #28은 main `39e53d834b9ea03b2920da81f7557c591492e1a8`에 병합됐다. 기획 시 제품 기준은 `d186d39158ee011e3ef2fcbbc42b0804e3fcbb03`이다.

## 사용자 결정

- 같은 조합은 경기 **종료 시점**의 기물 목록과 활성 시너지 종류가 같을 때다. 실제 마지막 전투에 투입됐는지는 확인할 수 없어 종료 시점 목록을 사용하기로 했다.
- 기물 성급, 장착 아이템, 증강과 시너지 활성 구간은 조합 구분에서 제외한다. 기물·시너지 나열 순서는 무시한다. 같은 기물이 여러 개일 때는 실제 기록된 수량이 다르면 다른 조합으로 구분한다.
- 아이템·증강을 필터로 고르면 선택 조건에 맞는 참가자 관측만 대상으로 통계를 다시 계산한다. 서로 다른 조건을 함께 고르면 같은 참가자 관측이 모두 충족해야 한다. 각 항목은 기존 화면처럼 하나씩 선택한다.
- 사용자는 상대 비교에서 양쪽 중 어느 한쪽만 모든 선택 조건을 만족해도 비교하는 방식을 선택했다. 기물 A와 아이템 X를 함께 고르면 **기물 A가 아이템 X를 직접 장착한 관측만** 포함한다. 기물 필터 없이 아이템만 고르면 조합의 어느 기물이든 해당 아이템을 장착한 관측을 포함한다.
- 집계 캐시는 동일한 결과면 기존 것을 검증·재사용하고, 서로 다른 결과가 보관 한도에 도달하면 자동으로 삭제하지 않고 사용자가 직접 정리한다. 구현상 완성된 세대와 남겨진 임시 작업은 각각 32개를 상한으로 두고 경기 관측과 카탈로그는 정리 대상에서 제외한다.

## 구현 범위

1. 새로운 버전의 조합 키를 기물 목록과 `TierCurrent > 0`인 활성 시너지 ID로 구성한다. 성급·아이템·증강·시너지 구간 차이만으로 갈라지지 않는다. 지역·큐·티어 기록 라벨과 카탈로그 identity별 분리는 유지한다.
2. 아이템·증강 필터가 변하면 보존된 익명 관측을 기준으로 결과와 분모를 재계산한다. 실제로 포함된 관측 수에 최소 표본 100 이상을 적용하며 변경 중 과거 결과·CSV 저장을 무효화한다. 기존 여러 필터는 AND다. 관련 범위(패치·지역·큐·티어)는 합치지 않는다.
3. 상대 배치 비교는 사용자가 선택한 **두 조합 중 한쪽이 모든 선택 조건을 충족한 경우**를 유지한다. 아이템·증강을 포함한 조건은 하나의 참가자에게 함께 적용하고 기물과 아이템을 함께 고르면 그 기물에 장착된 아이템인지 확인한다. 원래 로비에서 같은 새 조합이 여러 참가자에게 나오면 필터로 참가자를 숨기기 전에 모호성을 판정하고 제외한다. 적격 로비만 사용하며 화면에 방향·표본·조건을 표시한다.
4. 하나로 합쳐진 조합의 마지막 참가자를 대표로 골라 그 사람의 성급·아이템·증강을 전체 공통값처럼 표시하지 않는다. 공통 기준인 기물·활성 시너지를 표시하고, 조건에 따른 통계임을 화면과 CSV에서 명확히 한다. 근거 없는 아이템·증강 대표값이나 상세 분포는 이번에 만들지 않는다.
5. 정책은 해당 집계에 실제 기여한 모든 관측의 증강 정보를 고려한다. 승인되지 않았거나 금지된 증강이 섞여 있으면 기존 `MetricPolicy`의 표시 제한을 보수적으로 적용하고, 필터 변경 후 해당 조건의 관측으로 다시 평가한다. 현행 정책에서 미분류·Legend 기반은 비율을 막고 평균은 허용하며, 알 수 없는 증강·Legend는 평균도 막는다. 조합 기준 완화가 정책 완화를 의미하지 않는다.
6. 동일 경기 충돌 감지는 조합 키와 분리해 기존에 검사하던 성급·기물별 아이템·증강·순위·라운드 등의 차이를 계속 탐지한다. 기존의 완성된 익명 관측과 카탈로그를 변경하지 않는다. 기존 저장소 복구는 미완성 기록 꼬리를 정리하고 인덱스를 복구할 수 있으며, 이번 변경이 추가한 동작은 아니다. 기존 집계 캐시와 다른 버전의 재집계를 사용해 이전 통계가 새 기준 결과로 보이지 않게 하며 실패·취소 시 기존 집계 파일을 보존한다. 다중 범위는 별도의 임시 세대에서 전부 완성한 뒤 게시한다. 동일 결과는 파일 이름과 실제 바이트를 확인한 경우에만 재사용하며, 상한 도달 시 기존 캐시를 보존하고 직접 정리 안내를 표시한다.
7. 실제 Riot API 호출은 추가하지 않는다. 합성 자료로 검증하고, 실제 저장 자료에서 새 결과가 나오는지는 별도로 구분한다.

## 완료 조건과 검증

- 같은 기물·활성 시너지의 성급/아이템/증강 변형은 하나로 합산되고, 기물 수량이나 활성 시너지 종류가 다르면 구분된다. 종료 시점 목록이라는 사실이 UI에서 명확하다.
- 필터 없음, 아이템만, 증강만, 동시 선택에 대한 독립 기대값과 99/100 표본 경계, 지역·큐·티어·카탈로그 분리를 검증한다. 기물 A가 아닌 다른 기물에만 아이템 X를 장착한 관측은 A+X 조건에서 제외한다. 선택 조건에서만 집계된 표본·분자·분모가 화면과 CSV에 일치한다.
- 하나의 로비에 같은 조합이 여럿인 경우, 조건으로 일부만 남겨도 사전에 모호성이 판정되어 상대 비교에서 제외된다. 양쪽 중 어느 쪽이 조건을 만족했는지, 양쪽 정책 증강의 혼합·차단·미분류가 안전하게 반영되는지 확인한다.
- 정책 분류가 없거나 미확정인 증강을 허용값으로 추정하지 않는다. 필터 후 각 정책이 차단하는 평균·비율 및 관련 CSV 값이 노출되지 않으며, 현행 정책이 허용하는 평균은 유지한다.
- 동일 경기 해시의 다른 성급·아이템·증강 등의 충돌을 계속 감지하고, 구버전 캐시·관측과 새 결과가 혼동되지 않으며, 저장 실패·취소 및 UI 재계산 중 기존 자료를 보존한다.
- 변경 기능 관련 테스트부터 실행한다. 집계·저장·정책의 공통 계약 변경으로 여러 기능에 큰 영향이 확인되므로 영향 범위 검토와 함께 전체 EditMode도 수행한다. 실제 API 및 민감 원문은 사용하지 않는다. Unity 창 검증은 소유 창 및 기존 창 보존 절차를 따른다.
- 독립 코드 검수·QA, 문서와 사용법 정리, 기능 변경에 대한 최신 CodeRabbit 검수를 거쳐 별도 PR로 관리한다. 사용자의 실제 통계 사용 가능성은 합성 테스트 통과만으로 보장하지 않는다.
