# 정적 카탈로그 비교 화면의 원문 표시

상태: 구현·실행 검증·독립 최종 QA 완료, PR 전. 기준 main ba50db8.

## 변경과 사용법

데이터 관리 탭의 카탈로그 변경 비교에서 이전·이후 값과 ID에 포함된 `<b>`, `<color>` 등 태그를 화면 서식이 아닌 문자 그대로 표시한다. 항목 Foldout 제목도 동일하다. 카탈로그 두 개를 선택해 비교하는 기존 사용법과 비교 방향은 같다. 비교 결과를 새로 생성해도 같은 규칙을 적용한다.

변경 대상은 비교 화면 하위의 Label 표시 설정이다. 원문 문자열, 카탈로그 저장·해시, 차이 계산, 다른 화면 및 실제 API 호출은 변경하지 않는다. 관계·효과·출처의 문자열 구분자 충돌은 [별도 확인된 문제](CollisionInvestigation.md)이며 이번 표시 수정으로 해결하지 않았다.

## 검증

- Unity 컴파일 completed, failed=false. 신규 비교 화면 테스트 3건이 수정 전 예상대로 실패했고 수정 후 DataManagerTabTests 10건 전체가 통과했다. 전체 EditMode는 1,021건 중 1,019통과·실패 0·호스트 제약 2건 건너뜀이다.
- 합성 카탈로그 2개를 사용한 `-StaticComparison` 검증은 940px/500px 각 4개, 총 8PNG를 생성했다. 두 자료는 각각 검증 오류 0·아이콘 누락 경고 1이며 도구는 실제 검증 숫자를 표시한다. 전후 설명은 279/265 UTF-16 코드 단위로 비BMP 문자를 포함한다. 모든 이미지를 root가 직접 열어 태그 원문, 전후 값과 끝 표식을 확인했다. 화면보다 긴 임의 문자열 전체까지 검증했다는 뜻은 아니다.
- 정상 화면 검증 및 표시 전/후의 예외 probe에서 기존 EditorWindow 9개·native ContainerWindow 1개와 원래 포커스를 보존했고, 생성한 창·추가/누락 프레임은 0개였다. Unity 창은 소유 객체만 정리했다. 실제 API를 호출하지 않았다.
- 독립 코드검수가 긴 문자열·합성 경고 수의 검증 보완을 지적했고 보완 후 delta 재검수에서 추가 차단 지적이 없었다. 독립 최종 QA는 최신 8PNG를 직접 열고 창 정리 증거와 테스트 범위를 대조해 필수 지적 없이 통과했다. QA는 Unity 테스트를 직접 실행하지 않았고 root의 실행 결과를 구분했다.

결과 JSON과 PNG는 Git에서 제외되는 `Library/TftAnalyzerValidation/comparison-catalog-visual-*` 및 `catalog-window-*-comparison-*.png`에 있다. 저장소에 포함된 18.2 카탈로그의 파일은 제품 변경 대상이 아니다. 실제 화면 검증은 창작 자료에 대한 결과다.
