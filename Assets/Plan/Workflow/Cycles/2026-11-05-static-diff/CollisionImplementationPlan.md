# 정적 카탈로그 비교의 구조적 충돌 수정 계획

상태: 구현·검증 후 PR #27 검수 중. 기준 main ba50db8이며 선행 PR #26의 표시 개선은 main에 병합됐다. 이 상태 문구는 현재 작업 트리의 문서다. 기존 API·카탈로그·보호 파일·정상 비교 결과를 보존한다. 증거와 남은 검수는 [결과 기록](CollisionResults.md)을 따른다.

## 문제와 목표

서로 다른 관계 ID 목록·효과 사전·출처가 동일한 구분자 연결 문자열이 되면 현재 비교기가 변경을 놓친다. Unity의 실제 비교기와 검증기로 세 합성 예제에서 재현했으며 기존 사용자 카탈로그에서 발생했다는 증거는 없다. [재현 기록](CollisionInvestigation.md).

원본 자료의 구조로 변경 여부를 정확히 판정하고, 비교 화면에서 실제로 다른 이전/이후 값이 구별되게 표시한다. 기존 `FieldChange` 생성자·FieldName·Before·After·일반 문자열과 정적 카탈로그 파일을 바꾸지 않는다. 충돌 사례에서는 공개 Before와 After가 같아도 구조가 다르면 변경 항목으로 남긴다.

## 비교 계약

- 관계 ID 목록은 Ordinal 정렬한 원소와 개수로 비교한다. 원소 순서는 무시하고 중복 개수는 보존한다.
- 효과 사전은 Ordinal 키 순서의 키와 기존 R/InvariantCulture 값 표현을 원소별 비교한다. 사전 삽입 순서만의 차이는 무시한다.
- 출처는 기존 SourceName→Url 안정 정렬 후 SourceName·Url·ETag·Sha256·IsSupplemental을 원소별 비교한다. 이름/URL 동률의 기존 입력 순서와 중복 개수는 보존하며 RetrievedUtc만 다른 경우는 계속 무시한다.
- 같은 ID가 여러 개면 현행 첫 번째 항목을 쓰는 정책과 다른 필드의 기존 비교를 변경하지 않는다. 원본에 포함된 구분자를 금지하거나 데이터 파일을 변경하지 않는다.

## 화면 계약

비교 당시의 검증된 이전/이후 카탈로그에서 같은 종류·StableId·현행 첫 항목 기준의 원래 구조를 읽어 관계·효과·출처의 표시 행을 구성한다. 현재 활성 선택이나 유사한 이름으로 다시 찾지 않는다. 대응 자료를 확보하지 못하면 추정하지 않고 고정 안내를 표시한다.

실제 제어문자와 문자 그대로의 `\\u001f`, 실제 줄바꿈과 `\\n`, 따옴표·역슬래시와 원소 경계가 구별되도록 인용/escape한다. 모호한 구 연결 문자열을 Split해 원래 구조를 추측하지 않는다. 공개 Before/After는 바꾸지 않으며 UI 표시 객체를 별도로 둔다. 긴 값은 생략 여부를 알리고 나머지 접근 경로를 제공하며 UTF-16 대리쌍을 끊지 않는다. PR26의 태그 원문 표시 및 작은 창·소유 창 정리 계약은 유지한다.
