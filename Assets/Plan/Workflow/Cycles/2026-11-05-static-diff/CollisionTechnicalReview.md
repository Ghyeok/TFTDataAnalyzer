# 정적 비교 충돌 기술 검토

상태: 독립 읽기 전용 GPT 검토 완료, 제품 수정 전. 기준 main ba50db8. 현재 외부 기획 A 승인 대기와 별개로 실행 가능한 수정안·검증 조건을 준비했다.

## 기존 동작의 실제 확인

Unity 합성 probe `Library/TftAnalyzerValidation/StaticDiffBaselineProbe.cs`로 현재 실제 비교기에 자료를 넣었을 때, 시너지 목록과 효과 사전의 입력 순서만 바뀌고 출처 조회 UTC만 바뀌면 변경 기물 0개였다. 이름을 변경한 카탈로그 쌍은 비교 방향을 바꿨을 때 이전·이후 값이 서로 바뀌었다. API 호출과 EditorWindow 생성은 없었다. 이 확인은 합성 데이터에 한정된다.

현재 Unity의 `TFTAnalyzer.Tests.Diff.CatalogDifferTests`를 실행한 결과 2개 중 2개 통과, 실패·제외 0개였다. 두 테스트는 추가/삭제/이름 변경과 출처 조회 시각만 다른 경우를 다루며, 앞서 재현한 구분자 충돌은 포함하지 않는다. 기존 테스트 통과는 충돌 결함의 해결이나 전체 비교 기능의 검증을 뜻하지 않는다. 컴파일은 실행 전 completed·실패 false였다.

## 권고안

- 기존 공개 `FieldChange.FieldName`, `Before`, `After`와 생성자 및 일반 문자열 출력은 보존하고, 변경 여부는 관계 목록·효과 사전·출처 각각의 원래 구조에서 판정한다. 서로 다른 자료구조가 기존 공개 문자열로는 같더라도 변경을 걸러내지 않는다.
- 관계 ID는 Ordinal 정렬한 원소와 개수를 비교한다. 순서는 무시하고 중복 개수는 유지한다. 효과는 정렬된 키와 기존 R/InvariantCulture 값 문자열을 원소 단위로 비교한다. 출처는 기존 SourceName→Url 안정 정렬과 동률 순서를 유지한 채 SourceName·Url·ETag·Sha256·IsSupplemental을 비교하며 RetrievedUtc는 계속 제외한다.
- 비교 화면은 양쪽 검증된 카탈로그의 원래 구조에서 표시 행을 만들어 구분한다. 연결된 구 문자열을 분해해 목록 경계를 추정하지 않는다. 실제 제어문자, 글자 그대로의 역슬래시 표기, 줄바꿈, 원소 경계가 구별되게 표시하고, 화면의 동적 Label 및 Foldout 제목에서 rich text 해석을 끈다. 원본 카탈로그 파일은 수정하지 않는다.
- 공개 `FieldChange`에 새 표시 속성을 추가하면 기존 직렬화 결과가 달라질 수 있다. 표시 계층에서 별도 표현을 생성하는 대안을 우선 검토하며 구현 전 실제 호출 경로를 검수한다.

## 필수 검증

1. 기존 실제 probe의 효과 사전·시너지 목록·출처 세 충돌을 실제 코드의 실패 테스트로 만들고 수정 후 각각 올바른 필드 변경이 발견되는지 확인한다.
2. 일반 `Before/After`가 기존과 바이트 단위로 같고, 충돌 사례도 기존 공개 문자열의 의미를 바꾸지 않으면서 변경을 발견하는지 검증한다.
3. 관계 순서 무관·중복 개수, 효과 키·값·입력 순서·문화권, 출처의 5개 필드·동률 안정 정렬·중복·조회 시각 무시, 빈 값·추가/삭제·비교 방향을 검증한다.
4. 실제 화면에서 구조화 전후 값이 구별되고 임의 제어문자를 목록 경계로 오해하지 않으며 리치텍스트를 실행하지 않는지 합성 UI 및 소유 창 화면 캡처를 확인한다. 기존 카탈로그·정규 JSON·해시를 보존한다.

범위는 논의·기획용이며 제품 구현·사용자 카탈로그에서 실제 충돌 발견·Antigravity 검토 완료를 뜻하지 않는다. 위 권고는 독립 GPT 담당의 읽기 전용 검토이며 외부 문서 전송이나 API 호출을 수반하지 않았다.
