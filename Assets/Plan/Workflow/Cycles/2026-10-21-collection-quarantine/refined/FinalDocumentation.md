# 수집 격리 보고서 사용법

2026-10-21. 상태: 승인 대기. 승인 구현·코드검수·QA 통과, PR 검수·병합 대기. 사용자 최종 결과 승인은 별도다.

경기 수집 중 현재 카탈로그에 없는 기물·아이템·시너지·증강 ID가 있으면 해당 경기 전체를 격리한다. 이전에는 제외 건수만 남았지만 이제 안전한 진단을 로컬 보고서로 보존한다.

1. 기존과 같이 검증된 카탈로그와 수집 조건을 선택해 직접 수집을 승인한다.
2. 결과의 ‘필터 제외’와 ‘격리’ 건수를 확인한다. 격리는 필터 제외의 일부이며 패치·큐 불일치와 같은 뜻이 아니다.
3. ‘보고서 저장됨’이면 해당 요청 조건의 마지막 격리 실행을 기록한 것이다. 격리0이면 이번 보고서가 없으며 과거 파일을 이번 결과로 표시하지 않는다.
4. ‘보고서 저장 실패’는 진단 파일을 남기지 못했다는 뜻이다. 이미 저장한 익명 관측은 보존되며 자동 재시도하지 않는다.
5. ‘상한 도달로 일부 누락 · 수집 중단’이면 고유 진단4,096개 상한 때문에 다음 요청을 시작하지 않은 것이다. 보고서는 전체 진단을 보존한 결과가 아니다.

취소·요청 제한·시도 상한으로 끝나도 그때까지 얻은 진단은 종료 후 한 번 저장을 시도한다. 환경 설정 확인·입력 변경은 지난 결과를 지우지 않으며 새 수집을 시작하면 이번 실행으로 초기화한다.

보고서는 기존 로컬 저장소의 diagnostics/quarantine/<contextHash>.json에 있다. 요청 context와 알 수 없는 ID는 해시로만 기록하고 종류와 실행 종료 UTC·격리 건수·부분 누락 여부를 함께 보존한다. 원문 ID·PUUID·이름·키·Match ID/해시·경기별 연결을 남기지 않는다. 정상 관측·카탈로그를 덮어쓰거나 미확인 증강을 허용하는 기능이 아니다.
