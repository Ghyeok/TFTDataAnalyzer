## Missing decisions and recommended defaults

1. **Snapshot loading and rebuild.** `AggregateStore` currently has only `SaveAsync`; there is no load/discovery API. Current aggregate JSON retains fingerprints and augment IDs but loses unit/active-trait/item descriptors. Task 4 cannot implement the required entity filters from that JSON alone. Add the smallest analysis service/reader contract necessary. A reasonable default is an explicit local Refresh/Rebuild operation that reads validated anonymous observations once, derives aggregate + composition descriptors from that exact snapshot, applies policy, and publishes immutable view data. Keep aggregate cache persistence behind that explicit operation. If instead cache-first loading is chosen, add a strict reader plus descriptor source and stale/missing descriptor behavior; do not guess entities from a hash. No need to change old schema-1 cache files or generated catalogs.
2. **Implicit reads can write.** `ObservationStore.ReadAllAsync` recovers tails, republishes the processed index and creates store directories under a lease. Do not trigger this automatically from window open, `CreateGUI`, tab changes, catalog synchronization or filters while describing those actions as read-only. Explicit Refresh/Rebuild makes the recovery/write boundary visible. Rebinding must never duplicate it.
3. **Filter meaning.** Use AND across dimensions and exact stable-ID membership for unit, active trait, equipped item and augment. Choose one selection per entity category initially; labels may search Korean/English catalog names, but matching uses stable IDs. An entity filter narrows whole composition rows; it does not create a new per-unit aggregate or pool counts from unlike boards. Active traits match `IsActive`, consistent with fingerprints.
4. **Pairwise filtering.** Apply all entity predicates to one endpoint as a whole; include a pair when either complete endpoint matches. Do not satisfy a unit predicate on A and an item predicate on B. Preserve stored first/second orientation rather than silently reversing estimates. State this endpoint interpretation next to filters or pairwise table.
5. **Scope filters.** Patch follows active verified catalog; switching patches uses existing data selection and clears the old analysis snapshot immediately. Region/queue/tier selectors expose exact available values. `ALL` as a stored tier label is distinct from a UI `전체` selection. A UI all-selection lists distinct scope rows; it never merges regions, queues, tiers or catalog identities. Tier remains the caller-supplied collection label, not authenticated participant rank.
6. **Filter and snapshot state.** Preserve filters and last completed immutable snapshot during UI reconstruction of the same catalog; close disposes callbacks and cancels owned loading. A catalog switch invalidates previous rows/export immediately. Invalid drafts should not retain an apparently valid export. If loading is asynchronous, bind each completion to the starting catalog/generation and ignore stale completions.
7. **Empty/error states.** Distinguish no active catalog, no local snapshot, explicit refresh in progress, no rows matching filters, and safe load/rebuild error. Show selected scope and the loaded snapshot's observed match period when it exists, with clear wording that it is the loaded scope period; do not invent a date range for absent data. Do not convert a corrupted store into a successful empty result. Permit retry after a safe failure.
8. **CSV shape.** Export the current filtered presentation snapshot only through a typed `MetricPresentation` export boundary. One record per allowed ratio; for a suppressed composition/pair emit one state record with ratio-specific fields blank. Include metric kind, composition identifiers/direction, all scope fields, sample count, nullable average, observed period, policy state/note, ratio name/numerator/denominator/rate/bounds where allowed. Invariant numeric format and UTC ISO timestamps; define estimate/bounds as fractions 0–1 in the headers or accompanying copy. Escape quotes/newlines/commas and neutralize text that spreadsheet programs would interpret as formulas. A canceled save dialog writes nothing. Keep errors free of arbitrary exception contents or observation fragments.
9. **Local export authority.** Local CSV is already authorized and needs a deliberate user action/path selection. It works without an API key or registration acknowledgement. Do not add public export or gate local CSV behind the future registration control. Reject destination behavior that overwrites source observations, aggregate caches or generated catalogs. Preserve an existing export on precommit write failure where feasible.

## Acceptance criteria and risks

- Verified schema 2 and verified legacy schema 1 selection flow through analysis; mismatched/unverified identity never exposes stale rows or exports.
- 99 vs 100 participant samples and 99 vs 100 eligible pairwise samples demonstrate the threshold; a higher configured threshold works and values below 100 are rejected.
- All blocked reasons are represented safely; missing augment metadata does not turn into visible ratios. Tests inspect CSV cells for completely blank suppressed ratio fields, not merely absence of a percent sign.
- No filter or UI reconstruction invokes HTTP, observation recovery, cache saving, or a duplicate load; explicit Refresh/Rebuild publishes a coherent snapshot and safe retry/cancellation behavior.
- Unit/trait/item/augment intersections prove stable-ID filtering and coherent pair-endpoint semantics. Different region/queue/tier/catalog scopes never pool counters.
- Both tables show sample definitions, policy state, observed period, allowed average/ratios and 95% Wilson intervals; pair direction and ambiguity exclusions remain intelligible.
- CSV uses only approved DTO numeric fields, keeps suppressed fields blank, contains no match hashes/raw observations, and handles Unicode/escaping/formula-like text/cancel/failure safely.
