# Task 5 구현 요청

2026-10-19. 역할: 구현 에이전트. 요청 모델 GPT-6.1 Sol / High. 이유: 설정 IO 복구·취소 없는 동기 빌드 콜백·다중 UI 연결의 일관성을 구현한다.

## 실제 실행 메시지

`Assets/Plan/Workflow/Cycles/2026-10-19-compliance-gate/raw/DevelopmentRequest.md`를 읽고 그 구현 계약에 따라 Task 5 전체를 구현하라. 첫 단계는 테스트와 최소 컴파일 스텁만 작성하고 RED_READY를 보내는 것이다. Unity 실행은 root만 하며, root의 RED 확인 전 실제 구현을 하지 않는다. 한 기능을 끝까지 맡고 추가 에이전트·Git 쓰기·네트워크·Hermes 호출을 하지 않는다. 최종 응답은 변경·테스트·제한을 1500자 이내로 반환한다.

## 구현 계약

- 승인 계획: [ImplementationPlan](../refined/ImplementationPlan.md). 사용자 “워크플로대로 진행해줘” 승인. Task 6은 제외한다.
- 쓰기 범위: `Assets/TFTAnalyzer/Editor/Compliance/`, `Editor/UI/About/`, 해당 Compliance/UI 테스트, 기존 `TftDataAnalyzerWindow.cs/.uxml/.uss`의 필요한 연결만. 기존 파일 변경을 보존한다. 다른 제품 기능·문서·검증 도구는 root가 관리한다.
- 부모 역할은 개발 리드/통합자다. 에이전트는 구현만 담당하고 검수자·QA를 생성하지 않는다. 현재 작업 디렉터리를 사용한다. 전체 과거 대화·raw 보고서를 읽지 않는다.
- 기존 관련 구현과 테스트 패턴을 필요한 만큼만 읽는다. UI Toolkit·TDD·간결한 변경 스킬을 적용한다. 시리얼라이즈 필드는 계획의 네 개만, 키·seed·PUUID를 읽거나 쓰지 않는다.
- 첫 단계: 계획 전체 기능의 핵심 실패 테스트와 컴파일 가능한 최소 스텁을 작성한다. 테스트는 실제 메서드/콜백/파일·UI 동작을 확인하고 하드코딩 실패나 소스 문자열만으로 통과시키지 않는다. 테스트 창은 기존 `OwnedEditorWindowScope`로 소유한다.
- 완료 후 `RED_READY`와 root 실행용 정확한 fixture 필터를 보낸다. Assets 파일 수정을 멈추고 root의 실패 결과를 기다린다. 상태 기록에 동기화 지점을 명시한다.
- root가 RED를 확인해 허가하면 최소 구현으로 전체 요구를 충족한다. `GREEN_READY` 뒤 다시 Assets 편집을 멈춘다. root만 컴파일·Unity 테스트를 실행한다. Unity CLI나 Unity 프로세스를 직접 실행하지 않는다.
- 설정 읽기/탭 전환은 저장·네트워크를 하지 않는다. 손상/읽기 실패/알 수 없는 값은 배포 차단, UI 오류는 고정 문구만 쓴다. 로컬 상태는 Riot 온라인 승인 검증으로 표시하지 않는다.
- 기존 경로 보호를 재사용하고 `compliance.json` 자체·임시 파일·교체 직전 대상을 검사한다. 저장 실패 후 이전 파일과 화면을 보존하며 임시 파일을 정리한다. 테스트용 교체 실패 주입은 최소 범위로 둔다.
- 빌드 콜백은 실제 설정을 매번 읽는 같은 검증 함수를 호출한다. 실제 Player 빌드는 실행하지 않는다. 기본 생성자와 주입형 테스트 둘 다 동작한다.
- Project Settings 상태 초안과 저장 결과를 구분하고, 명시적 Portal 확인 없이 확인 시각을 만들지 않는다. About 재진입은 최신 저장 결과를 읽는다. RebuildUI/OnDisable 구독 정리·중복 0을 테스트한다.
- 고정 정책 URL 세 개와 원문 고지의 출처는 승인 계획에 있다. 필요한 고지는 원문과 제품명으로 표시하고 별도 한국어 요약을 제공한다. root가 정책 원문을 확인했으며 임의의 법적 승인 문구를 추가하지 않는다.
- 기존 개인 연구용 CSV를 등록 미확인/확인/철회 세 상태에서 저장하고 비율 억제 필드가 비어 있음을 확인한다. 등록 상태를 기존 분석/수집 서비스에 결합하지 않는다.
- root 테스트에서 실패하면 실패 증거가 가리키는 부분만 수정하고 다시 준비 신호를 보낸다. 실제 실행 전에는 통과·전체 완료를 주장하지 않는다. 짧은 결과에 구현 범위, 테스트 fixture, 검수자가 볼 위험만 적는다.
