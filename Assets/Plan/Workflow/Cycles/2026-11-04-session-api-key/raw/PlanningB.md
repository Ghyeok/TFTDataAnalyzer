## 응답

**기획 B 판정: revise.** 제안 범위와 비저장 원칙은 적절합니다. 구현 전에 아래 두 계약을 구체화해야 합니다.

**필수 지적**

1. **창·UI·VM·클라이언트의 수명을 구분해야 합니다.** 입력 문서는 UI 재구성 시 VM을 정리한다고 설명하면서, 같은 창의 세션 키와 기존 클라이언트의 rate limit 상태는 유지하도록 요구합니다. 세션 provider와 재사용 클라이언트의 소유자를 명시하고, UI 재바인딩으로 어느 객체까지 교체되는지 확정해야 합니다. 검증에는 같은 창 재구성 후 세션 키 유지·입력 필드 공백·rate limit 유지·이벤트 중복 없음과 창 종료 후 새 창의 세션 키 부재를 포함해야 합니다.

2. **취소와 키 해제 사이의 동작을 확정해야 합니다.** 취소 요청은 실제 작업 종료와 다를 수 있습니다. 작업이 남은 상태에서 세션 키를 지우면 후속 키 조회가 환경 키로 전환될 가능성을 배제해야 합니다. 창 종료·도메인 리로드 시 새 요청을 차단하고, 취소된 작업이 환경 키로 재시도하지 않도록 수명 계약과 테스트를 명시하십시오. 이미 전송된 요청이나 만들어진 문자열의 보안 삭제까지 보장할 필요는 없습니다.

**필수 검증 보강**

- 401뿐 아니라 **403도** 세션 키 사용 후 환경 키 대체·재시도 없음과 실제 요청 횟수를 검증하십시오.
- 공백 제거와 제어 문자 거절 순서를 기존 provider와 일치시키고, 제어 문자가 포함된 입력이 정리 과정에서 허용되는지 확인하십시오.
- 비밀 누출 검증은 화면 문구뿐 아니라 중첩 예외·전송 오류·로그 경로까지 포함하십시오. 입력 필드 내부 값과 가짜 전송의 인증 헤더는 기능상 필요한 값이므로, 이들까지 “sentinel 없음”으로 검사하는 모순은 피해야 합니다.

**선택 제안**

- 입력 크기 상한을 두어 과도한 붙여 넣기를 제한하십시오. 구체적인 키 형식 제한은 별도 근거 없이 추가하지 않아도 됩니다.
- 삭제 후 환경 키로 돌아간다는 동작을 버튼 주변에 짧게 안내하면 사용자가 상태 변화를 이해하기 쉽습니다.

두 동결 문서 외에는 열람하지 않았습니다. 실제 구현의 누출·수명 결함이 확인됐다는 뜻은 아니며, 승인 전 계획의 모호성을 지적한 것입니다. 네트워크·Unity 실행·파일 변경·재위임은 수행하지 않았습니다. 실제 모델·추론 설정·사용량은 확인할 수 없습니다.
