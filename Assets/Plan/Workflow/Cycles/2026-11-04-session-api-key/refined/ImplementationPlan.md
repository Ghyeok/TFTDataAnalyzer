# Unity 세션 API 키 입력 계획

상태: 반려됨 — 사용자가 작업을 취소하고 기존 환경 변수 방식을 유지하기로 했다.

## 목적과 사용자 결정

개발용 Riot API 키 갱신 때마다 Windows 환경 변수를 편집하고 Unity Hub/Editor를 재시작하는 불편을 줄인다. 사용자가 경기 수집 탭에 키를 붙여 넣으면 현재 도구 창의 메모리에서만 사용한다. 개발용 키의 갱신 자체를 자동화하지 않는다. 기존 경기 5건의 데이터 형식 실패(KI-003)를 해결했다고 주장하지 않는다.

사용자 선택은 Unity에서 붙여 넣어 현재 실행에만 사용이다. 상위 설계 §8.3은 환경 변수 또는 OS 자격 증명에서만 읽도록 제한한다. 위 사용자의 새 선택으로 동일한 비저장 원칙을 지키는 창 메모리 입력을 해당 출처 목록에 추가하는 변경을 이번 승인 범위에 명시한다. 프로젝트 파일·EditorPrefs·Unity 직렬화·환경 변수·명령줄·로그·분석/협업 자료·저장소에 키를 쓰지 않는다. 시스템 클립보드의 수명은 운영체제에 따르며 앱이 클립보드를 저장하거나 변경하지 않는다.

## 제안 동작과 경계

1. 경기 수집 탭에 가려진 키 입력 필드, '이번 창에 적용', '입력한 키 지우기'를 둔다. 새 키는 사용자가 직접 붙여 넣는다. 예시·테스트는 창작 가짜 값만 사용한다. 비밀 입력 필드는 암호 마스킹, view-data 영속화/직렬화 비활성, 디버깅 텍스트·예외 원문 금지. 적용 후 필드를 즉시 비운다. 문자열을 메모리에서 안전하게 0으로 지웠다고 보장하지 않는다.
2. 입력한 유효 키가 있으면 환경 변수 키보다 우선한다. 사용자가 지우면 해당 창에서 입력값 참조를 버리고 기존 환경 변수 경로로 돌아간다. 입력 키가 401/403이어도 환경 변수로 자동 대체하거나 재시도하지 않는다. '설정됨'은 형식 존재일 뿐 서버 유효성을 뜻하지 않는다.
3. 선택 키는 현재 창·도메인의 메모리에만 둔다. 창 닫기·도메인 리로드/Unity 종료에서 참조와 입력 UI를 해제한다. 화면 재구성은 같은 창의 비직렬화 상태만 유지하고 시각 입력값은 복원하지 않는다. Unity 프로세스 메모리/OS 클립보드까지 보안 삭제 보장은 하지 않는다. 여러 창의 키는 창별로 독립한다.
4. 수집 중 키 입력·적용·삭제를 막아 단일 작업 중 키가 바뀌지 않게 한다. 키 변경은 API 요청을 시작하지 않으며 이미 존재하는 수집 조건 확인·401/403/429 중단 및 권한 경계는 유지한다. PUUID 입력/저장 방식을 바꾸지 않는다.
5. 잘못된 키(공백·제어 문자 등)는 값 없이 일정한 안내만 표시하고 이전 적용 키는 유지한다. 키의 앞뒤 공백은 기존 처리와 일치하게 제거한다. 키를 채팅/AI 도구·캡처에 넣지 않는다.

## 파일 책임과 검증

- 기존 IRiotApiKeyProvider에 부합하는 비직렬화 창 소유 세션 provider를 추가하고, 기존 EnvironmentRiotApiKeyProvider를 fallback으로 사용한다. 창이 CollectionViewModel·CollectionService·provider 및 재사용 클라이언트를 소유한다. 같은 창의 UI 재구성에서는 바인딩만 해제·재생성하고 VM/provider/클라이언트·rate limit 상태는 유지한다. 서로 다른 창의 상태는 공유하지 않는다. 창 종료/도메인 리로드에서는 새 요청을 차단하고 취소 요청 후 진행 중인 작업이 안전하게 종료되도록 하며, 취소 후 환경 키로 전환한 후속 요청이 나가지 않도록 보장한다. 안전한 참조 해제 시점은 비동기 종료와 함께 검증한다.
- CollectionTab과 TftDataAnalyzerWindow.uxml/uss에 암호 입력과 적용/삭제, 현재 입력/환경 키의 출처와 미설정 안내를 추가한다. 키 자체·길이·해시를 상태 화면에 표시하지 않는다. UI 생성/파괴 및 재구성에 대한 키 참조 정리·입력 필드 초기화, 이벤트 중복 방지.
- 실제 서버 통신 없이 가짜 키와 가짜 전송으로 미설정·환경 fallback·세션 우선·삭제·잘못된 입력·401/403시 자동 fallback 및 재시도 금지·수집 중 변경 금지·여러 창 독립·취소/종료·재구성/도메인 reload 모델·기존 rate limit을 테스트한다. 로그·상태 UI·직렬화/설정·중첩 예외/전송 오류·Unity 콘솔·PR 증거에 가짜 sentinel이 새지 않는지 테스트한다. 사용자의 입력 필드와 가짜 전송 헤더의 정상적인 값 전달은 이 금지 범위와 구분한다. 정상 입력과 선행/후행 공백·제어 문자의 기존 검사 순서 일치 및 입력 길이 상한을 검토한다. 내보내기·기존 데이터·KI-003 동작 유지.
- 940/500px 소유 창 및 정상/실패 cleanup, 실제 PNG는 모두 가짜 키만 사용하고 캡처에는 키가 없음을 확인한다. 기존 EditorWindow/native frame/포커스·사용자 창/Chrome·catalog/observation 보존. 기존 승인된 시각 검증 지침을 따르고 사전 도구 계약에 UI 추가 반영을 검토한다.
- 필요 최소 계획·보안 설명·사용법·QA/리뷰 기록을 갱신하고 독립 검수·QA·PR을 수행한다. 세션 키와 실제 API 호출 없이 검증한다. 변경 범위 밖 사용자 변경 및 키 문서는 건드리지 않는다.

## 경계 조건

Windows 환경 변수·Unity 재시작을 없애는 것이고 Riot 키 발급/갱신·개발용 유효기간을 없애지 않는다. 연결 테스트나 자동 수집, OS Credential Manager 영구 저장은 포함하지 않는다. 실제 수집 성공은 별도 미검증. 새 입력 경로와 보안/수명/에러 처리에 관한 고위험 리뷰 및 공개 가능한 근거를 승인 전에 정리한다.

## 기획 B 필수 지적과 처리

B는 동결 입력에 revise를 반환했다. 동일 창 UI 재구성 시 바인딩만 재생성하고 provider·클라이언트·호출 제한 상태를 유지하며, 취소 요청과 실제 종료를 구분해 키 해제 후 환경 키로 전환된 요청이 나가지 않게 한다. 401/403 무대체·제어 문자 검사 순서·중첩 예외/전송 오류 누출 테스트를 구체화했다. 입력 필드와 가짜 전송 헤더의 정상적 키 전달을 출력 누출과 혼동하지 않는다. 재검토 전이며 B pass를 주장하지 않는다.
