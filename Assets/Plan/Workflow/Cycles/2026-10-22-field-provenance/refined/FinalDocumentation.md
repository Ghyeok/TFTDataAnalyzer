# 필드별 출처 기록

상태: 승인 대기

진행 내역: 구현·독립 코드검수·전체 EditMode·독립 최종 QA 완료, PR 준비. 사용자 결과 승인·서비스 전체 완료가 아니다.

새 네트워크 정적 가져오기는 schema3 카탈로그에 선택한 값별 원본 문서를 저장한다. 한국어·영어 이름과 설명은 실제 언어 문서에, 비용·목록·효과는 실제 선택된 primary 문서에 연결한다. 병합에서 공식 값이 유지되거나 보완 값이 채워지는 기존 규칙은 유지한다. 효과 키의 `~`·`/`를 JSON pointer로 이스케이프하고 실제0을 누락과 구분한다. 필수 필드 출처·문서 연결·출처 프로필이 잘못되면 게시하지 않는다.

데이터 관리 → 카탈로그 내용 탐색 → 행 선택의 상세에 ‘필드별 출처’가 표시된다. 필드 포인터, 공식/보완, 원본 URL·SHA256을 일반 텍스트로 읽는다. 로컬로 변환된 아이콘의 출처는 원본 참조의 계보라고 표시한다. 통계 분류 허용·추천을 뜻하지 않는다.

기존 schema1/2 카탈로그는 파일·해시를 변경하지 않는다. 같은 전체 식별자의 구 팩이 있으면 구 스키마로 투영한 의미 값의 해시를 비교해 동일할 때 원래 팩을 재사용하고 실제 구 schema/catalog/hash를 반환한다. 필드별 정보가 저장되지 않은 구 팩에는 ‘필드별 출처 정보 없음’을 표시한다. metadata를 추측해 채우거나 자동 마이그레이션하지 않는다.

검증 증거의 진입점은 [체크포인트](../Checkpoint.md)와 [실행 기록](DevelopmentReport.md)이다. 원래 f005879 직렬화 코드를 일회성으로 실행해 생성한 창작 schema1/2 골든 JSON의 바이트·해시를 비교했다. 최종 전체796개 중794통과·실패0·호스트symlink2제외(83.32초), 새 출처31개 모두 통과했다. 실제 adapter→병합→아이콘staging→게시→loader, 구schema1/2 공식/보완 재사용, 외부 해시를 다시 계산해도 필수 출처 누락 차단, 출처만 다른 불변 충돌을 확인했다. 관련 가져오기69/69와 검수 수정28/28, 실제 PNG4장·정상/표시전후 예외 정리도 확인했다. 동결 소스19개·보호1399개 불변, 전체 전후 창·프레임·포커스 동일, Console오류0·경고0이다.

화면 검증의 첫 실행은 InvalidOperationException으로 캡처0장이었지만 기존 창·프레임 보존과 소유 창0은 확인했다. 합성 상태 진단을 추가한 1회 재실행에서4PNG가 통과했으며 첫 원인은 확정하지 못했다. 제품 오류나 KI-001의 원인 해결 증거로 바꾸지 않는다. 화면 도구는 원래 검증된 로컬 카탈로그 읽기 모드와 별도 `-FieldOrigins` 합성 모드를 제공한다.

실제 다운로드·Match API·환경 변수 변경은 실행하지 않았다. 실제 경기 검증은 사용자 요청대로 미뤘으며, 증강 분류 등록0·실제 n100 사용성·KI-001과 최종 사용자 검증은 전체 서비스의 잔여 항목이다. Hermes 예약은 삭제 상태를 유지한다.

PR21 보완 후 최신 검증: 전체797개 중795통과·실패0·호스트2제외(81.56초), 신규32개통과. 출처는 동일 문서별로 묶어 효과40개의 뒤쪽pointer까지 읽게 했고 새4PNG도 확인했다. 구골든2파일은 Windows autocrlf 체크아웃에서도 LF·SHA가 같다. 지연된 사후 Console2건은 Pipeline 전송 오류이며 즉시 post-test 샘플이 아니다. 상태·한계·검수 원문은 [PR21 보완](PR21RevisionReport.md)에 구분했다.
