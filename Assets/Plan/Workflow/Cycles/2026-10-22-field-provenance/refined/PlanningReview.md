# 필드별 출처 기록 기획 통합

상태: 완료

2026-10-22. 기준 main f0058799355cd2754f193eff38d7dd415cd700e6. [정제 계획](ImplementationPlan.md), [실제 요청·응답 및 사용량](../../../../../../AntigravityCollab/tasks/2026-10-22-field-provenance-planning/result.md).

기획 A(Antigravity)는 최초 동결 계획의 범위·정책을 pass로 판정했다. 기획 B(기존 GPT 담당)는 원본 부재로 만들어진 기본값과 실제 값의 출처 기록 누락을 구별할 규칙이 필요하다고 지적했다. root는 모델에서 필요한 포인터를 고정 규칙으로 계산하도록 정했다. 비용은 기존 유효 범위 1–9와 항상 필요한 출처를 유지하고, 효과의 실제 0은 키가 있으므로 출처를 요구한다. 빈 선택 문자열·목록은 부재로 처리하며 기존 값 검증은 완화하지 않는다. 해당 경로의 시험 완료 조건을 추가한 뒤 B는 같은 P2만 재검토해 해소/pass로 판정했다.

최종 계획은 schema3에 필드 출처를 저장하되 구 schema1/2 JSON·해시·불변 팩을 보존한다. 기존 팩을 재사용하면 실제 저장된 구 schema와 ‘필드별 출처 정보 없음’을 반환·표시한다. 모든 새 기록은 실제 선택한 문서에서 생성하며, 문서 단위 출처만 보고 누락된 필드 출처를 추측하지 않는다.

남은 개발·검수·QA 조건은 계획 Task1–3에 있다. 모델/직렬화/검증, 실제 공급·게시·다시 읽기, 탐색 표시를 순서대로 구현한다. 실행 증거 없이 통과로 표시하지 않는다. 기획 검토 시 제품 변경·Unity 제어·실제 API 호출은0이다. 실제 경기 수집은 사용자 요청대로 미룬다.

모델 확인 한계: A의 실제 모델/CLI/사용량은 원문 실행 기록에 있고 강제 접근 제한은 미검증이다. B의 실제 모델·추론·사용량은 미확인이다. 신규 담당자 생성 없이 기존 B를 재사용했으며, 같은 전체 기획의 반복 호출은 하지 않았다.

기획 종료 상태: **기획 A/B 필수 보완 해소**. 이후 사용자가 call_d0d2d56f0c514f2eb73afc534b641d3a에 “이 계획대로 구현 진행 (권장)”으로 명시 승인했다. [워크플로](../../../README.md) §3.1.6의 “사용자의 명시적 승인을 기다린다.”를 지킨 뒤 구현으로 전환했다. 승인 범위에는 실제 다운로드/API·환경 변경·분류 등록·집계 변경·공개 배포를 포함하지 않는다.
