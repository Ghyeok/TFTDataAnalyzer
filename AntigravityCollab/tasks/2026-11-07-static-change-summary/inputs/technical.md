# 현재 계약과 검토 쟁점

- `PatchManifest.PreviousPatchSummary`는 문자열이며 JSON serializer와 게시 manifest는 값을 보존한다. `DataDragonAdapter`는 생성 시 빈 문자열을 전달하고 `CatalogMerger`와 `StaticCatalogPipeline`은 이를 전달한다.
- `CatalogDiffer.Compare`는 네 종류별 추가 ID·삭제 ID·변경 레코드/필드를 반환한다. 비교 조건과 결과에 사용자 선택의 이전·이후 카탈로그가 필요하며, 화면은 구조화된 충돌까지 구별해 표시한다.
- `CatalogAssetWriter`는 같은 identity를 다른 내용으로 덮어쓰지 않고 콘텐츠 해시를 확인한다. 사용자가 기존 동일 identity의 카탈로그를 재요청하면 동일 의미의 구 버전을 재사용할 수 있다. 출처·구조·현지화 표·구 schema 1~4 바이트 보존은 필수다.
- 저장 요약에 비교 기준 identity·해시 또는 버전 관계를 어떻게 나타낼지, 다수 후보·프로필이 다른 후보·유효하지 않은 후보·동일 팩·최초 팩·기준 삭제·기준 변경·정렬을 어떻게 다룰지 결정이 필요하다. 문자열만 추가해 기준을 복구하지 못하거나 실제 직전 패치라고 단정하는 것은 위험하다.
- 콘텐츠 해시에 포함되는 값이 로컬에서 기준으로 무엇을 선택했는지에 따라 달라지면 동일 원본 재가져오기가 불변 충돌을 일으킬 수 있다. 기존 형식이나 매니페스트를 조용히 바꾸지 않는다. 원본 출처·표시 요약·기준 추적을 구분한다.
- 제약: 실행 범위 없는 자동 다운로드, 사용자 카탈로그 수정, 실제 Riot API, 비밀값, 미검증 값 추정 금지. 오프라인 합성 자료 및 실제 기존 카탈로그 읽기 전용 검증만 제안한다. 완료 조건은 추가·변경·삭제 건수, 명시된 기준, 기준 부재, 저장 실패/취소 및 기존 데이터 불변을 포함해야 한다.
