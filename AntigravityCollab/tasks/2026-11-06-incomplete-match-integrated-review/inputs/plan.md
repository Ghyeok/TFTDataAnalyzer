# 불완전 경기의 별도 보관과 열람 구현 계획

상태: 기획 A/B 통합안. 사용자께서 결정한 불완전 경기의 별도 보관·열람 방향을 구체화한 구현 범위다. 기준 main ba50db8ad5ef8dc6ef58153cee57da0f8555588c. 실제 경기 API 재호출과 일반 통계의 수용 조건 완화는 별도다.

## 사용자에게 보이는 결과

수집한 응답이 정상 저장 조건을 만족하지 못해도 안전하게 읽을 수 있는 부분은 별도 기록으로 보관해 확인한다. 목록과 상세에 `불완전 수신 기록 · 추가 확인 필요 · 정상 통계 제외`를 표시한다. 미지원 버전의 값에는 각각 `후보 · 의미 미검증`을 붙인다. 선택한 카탈로그의 이름·설명은 참고용이며 해당 패치에서 실제 경기가 진행됐다는 뜻이 아니라고 표시한다. 기존 실패 건수와 별도 보관 성공·실패를 구분한다.

## 입력·개인정보 계약

- 응답은 전체 8MiB 한도 내 엄격한 문법·중복 필드·깊이·자료형 검증을 끝내기 전 게시하지 않는다. 실패한 스트림 되감기나 추가 API 요청 없이 동일 응답에서 처리한다. 비밀값·식별자·원본 응답과 임의 문자열, 원본 버전 및 경기 시각은 디스크·UI·로그·예외에 두지 않는다. API 응답의 비밀 sentinel, 임의 속성과 예외 문자열을 합성 검증한다.
- 로컬 참가자 순번은 최대 8개이며 이름·PUUID는 버린다. 저장할 수 있는 숫자 후보는 정수로 된 순위 위치 1~8, 마지막 라운드 위치 0~100, 세트 번호 위치 1~99, 요청 큐와 일치하는 큐 값, 유닛 성급 위치 1~4, 특성 단계 위치 0~10이다. 이 범위는 메모리·형식 안전 상한이며 게임 규칙의 확정이 아니다. 값이 범위 밖이거나 형식이 틀리면 해당 상태만 보존한다.
- 기물·아이템·특성·증강 ID는 사용자가 선택한 검증된 카탈로그의 같은 종류에 정확히 일치하는 경우 그 카탈로그에서 가져온 ID만 사용한다. 응답의 임의 문자열·미확인 ID는 보관하거나 표시하지 않는다. 참가자별 유닛64·특성64·증강16, 유닛별 아이템16을 넘기면 부분을 정상인 것처럼 자르지 않고 해당 필드에 상한 초과를 표시한다.
- 필드는 존재/형식(`값 있음`, `명시적 빈 배열`, `누락`, `null`, `형식 오류`, `상한 초과`, `카탈로그 미확인`)과 의미(`확인`, `미검증`)를 구분한다. 미지원 버전의 모든 후보는 타입과 카탈로그 ID가 맞아도 의미 미검증이다. 예를 들어 빈 증강 배열은 `빈 배열 수신·의미 미검증`이며 `증강 없음`으로 단정하지 않는다.

## 저장·분리 계약

- 별도 데이터 모델과 저장 경로만 사용한다. 기존 ObservationStore·정상 중복 인덱스·집계·분석·CSV·카탈로그 파일과 섞지 않으며 기존 데이터를 수정하거나 자동 승격하지 않는다. 참고 카탈로그가 없어지면 숫자 후보만 표시하고 ID/이름은 `참고 카탈로그 사용 불가`로 처리한다.
- 각 기록은 저장소가 생성한 임의 파일명과 정상 인덱스와 공유하지 않는 도메인 구분 경기 ID 해시만 보유해 같은 경기의 반복 기록을 구분한다. 경기 ID 원문과 해시를 화면에 보이지 않는다. 해시 생성이 불가능하면 기록을 게시하지 않는다. 기존 정상 관측과 연결·자동 승격은 하지 않는다.
- 최대 기록당 256KiB, 전체 게시 기록 128건·32MiB를 적용한다. 저장 완료 후 30일을 보존 기간으로 하며 정리 대상은 전용 저장소 내부에서 이 기능이 만든 기록만이다. 상한·정리 실패 시 기존 정상 저장소에는 영향 없이 새 기록 저장을 중단하고 사용자에게 안내한다. 이 수치는 이번 기획의 기본 제안이다.
- 전용 저장소의 배타 잠금, 경로 이탈·reparse point 검사, 임시 파일의 검증 후 원자적 게시, 취소/예외 시 임시 파일 정리, 게시 후 취소의 일관성, 기존 기록 덮어쓰기 방지 및 손상 파일의 안전한 제외를 검증한다. 만료 정리는 타 기능·사용자 파일에 적용하지 않는다.

## 작업과 검증

1. [ ] 합성 데이터로 전용 후보 모델과 화면을 먼저 검증한다. 실제 관측과 유사한 미지원 버전·패치 미확인·증강 누락 상황에서 표시할 숫자·카탈로그 일치 항목이 있고 각 항목에 미검증이 남는지 확인한다. 지원 버전·null·누락·빈 배열·형식/범위 오류와 원본 식별자 sentinel도 시험한다.
2. [ ] 제한된 응답에서 후보를 추출하고 별도 저장/재열람을 연결한다. 구문 뒤쪽 손상·중복 필드·초과 크기·경로 공격·동시 쓰기·취소·저장 실패·손상 파일·상한·만료 정리를 검증한다. 정상 파서의 수용/거절 결과와 기존 데이터 파일을 보존한다.
3. [ ] 수집 결과 및 사용자 화면과 연결한다. 확인된 사실과 후보, 참고용 카탈로그와 실제 경기 패치의 구분이 재시작 뒤에도 유지되는지, 정상 집계·CSV·인덱스에 유입되지 않는지 검증한다. 소유 창의 실제 화면과 정상/예외 정리를 확인한다.
4. [ ] 독립 코드검수·QA와 전체 회귀를 수행하고 문서·PR로 정리한다. 실제 Riot API를 호출하지 않은 합성 검증임을 명시하며 이전 5건이 실제로 저장된다고 주장하지 않는다.
