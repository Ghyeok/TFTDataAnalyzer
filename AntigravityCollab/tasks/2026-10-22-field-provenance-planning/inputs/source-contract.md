# Current source contract for field provenance planning

Base main f0058799355cd2754f193eff38d7dd415cd700e6. Supplied evidence only; no credentials or Match API payloads.

Upper TFTDataPipeline.md section4 requires per-field provenance for CommunityDragon supplements; sections6.2-6.6 and7 require official priority and source attribution. The current implementation has document-level provenance but no persisted field map.

- UnitRecord/TraitRecord/ItemRecord/AugmentRecord each have Sources: IReadOnlyList<SourceStamp>. SourceStamp has SourceName, Url, RetrievedUtc, ETag, Sha256, IsSupplemental only. StaticCatalog currently has manifest and four record lists; no FieldOrigins. The canonical JSON record sources do not identify fields.
- DataDragonAdapter parses ko/en pairs; JoinedRecord supplies KoKr, EnUs and Primary. It creates records with paired document Sources. CommunityDragonAdapter reads its ko/en snapshots. Their values and selection behavior must stay unchanged; provenance must follow the actual contributing document, not a locale/prefix guess.
- CatalogMerger merges each field and emits MergeConflict (recordType,stableId,fieldName,officialValue,supplementValue,resolution) only on fills or differences. Equal values select official without a decision row. Effects are merged per key; official present zero is preserved by TryGetValue. Record source lists union document references. Merge decisions are currently transient.
- StaticCatalogPipeline promotes the loaded manifest to schema2, validates, stages icons, validates again, stages canonical data, publishes, updates index and refreshes AssetDatabase. After publish/index/refresh failure it reports one of the existing recovery states. It forwards merge decisions in StaticImportResult but does not persist field origins. The recently merged report UI is session-only.
- CatalogAssetWriter copies all four record types during icon staging and content-hash normalization. NormalizeSource sets RetrievedUtc to UnixEpoch and ETag empty; URL, hash and supplemental flag remain. Current published verification expects schema1 only for compatible official legacy, otherwise schema2. Thus schema3 support must reach verification/readers, not just serializer.
- Existing writer.Publish returns bool idempotent. Same full identity paths are immutable. The legacy schema1 official pack uses a guarded compatibility projection. A new verified publication result must not claim a schema3 catalog when it reused actual schema1/2 bytes; it must return the actually verified published hash/schema/catalog. Preserve bool callers and recovery ordering.
- PublishedCatalogLoader resolves index identity and canonical/legacy path, calls CatalogAssetWriter.VerifyPublishedHash, verifies index hash, deserializes catalog and runs CatalogValidator. Existing schema1 lacks Manifest.Identity; source-profile classification remains guarded official-only. Schema2 has full identity. Do not merge schemas with observation/aggregate schema numbers.
- CanonicalCatalogSerializer settings include fixed invariant culture/UTC/newlines and TypeNameHandling.None. Source stamps are canonical fields. Existing schema1/2 JSON/hash must remain byte/hash compatible; optional top-level fieldOrigins must be omitted there, not emitted as null or empty. Metadata injection into old schema must not bypass the hash.
- CatalogBrowserViewModel currently displays record fields and document Sources. It can expose a new catalog-level FieldOrigins list per selected record. Old packs should say field metadata is unavailable, not infer per-field origin from combined Sources. No classification permissions follow from provenance.
