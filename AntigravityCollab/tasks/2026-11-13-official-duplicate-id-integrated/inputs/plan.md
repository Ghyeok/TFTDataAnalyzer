# 공식 카탈로그 원본 ID 충돌 처리 계획

상태: 기획 초안. 기준: 병합된 PR #32 및 로컬 main 포함 커밋 `281baa4`. 사용자 구현 승인 전.

## 확인된 문제
공식 문서의 서로 다른 JSON 키가 같은 내부 `id`를 가진 경우 `ReadRecords`의 사전 대입이 앞 항목을 덮어쓴다. 가짜 아이템 두 개로 Unity 실제 파서 경로를 실행해 에러 없이 한 개로 합쳐짐을 확인했다 (`Library/TftAnalyzerValidation/duplicate-source-id-diagnostic.xml`). 실제 16.22.1 공식 8문서의 ID 중복은 0건이었다. 다른 버전에서 발생한다는 주장은 아니다.

## 제안
- 원본 행을 ID로 합치기 전에 보존하고, 기존 세트 규칙과 챔피언 접두어 발견에 필요한 모든 행을 사용해 범위를 판정한다. 선택한 범위에 실제 영향을 줄 수 있는 동일 문서·언어·항목 종류의 ID 충돌은 동일 값 여부를 추정하지 않고 오류로 중단한다. 부분 게시하지 않고 기존 카탈로그를 보존한다.
- 선택 범위 밖에만 있는 충돌은 안정적·제한된 경고로 보고하고 선택된 항목에 영향을 주지 않는 경우에 한해 가져오기를 계속한다. 경계가 애매하거나 접두어 발견 결과에 영향을 주면 안전하게 중단한다.
- 한국어와 영어의 같은 ID는 정상적인 번역 연결이다. ID가 없는 행은 기존 규칙대로 원본 키를 사용하며, 명시 ID와 대체 키가 충돌하는 경우도 같은 문서·언어에서 검출한다. 검증 범위·항목 유형·언어·제한된 충돌 정보를 가져오기 보고서에 알려 사용자가 확인할 수 있게 한다. 원본 응답 해시·기존 카탈로그의 형식과 저장 방식은 유지한다.
- JSON 중복 속성 검증, Riot 증강 문서의 한정된 metadata 예외, CommunityDragon의 별도 검증은 변경하지 않는다. 공식 카탈로그 기준과 결합된 보완 자료에서 ID 충돌을 조용히 잃지 않아야 한다.

## 검증 계획
1. 항목별·언어별로 서로 다른 키/같은 ID, 같은 값/다른 값, ID 미지정 대체 키와의 충돌을 합성 데이터로 재현한다. 언어 간 정상 결합은 유지한다.
2. 같은 세트·다른 세트 충돌, 선택 범위 외 충돌, 같은 ID가 경계를 넘는 경우, 챔피언 접두어 발견과 원본 순서 변경을 검증한다. 경계가 확실하지 않으면 실패하도록 한다.
3. 실패 시 기존 게시물 불변과 부분 게시 방지, 보고서의 제한·결정적 표시, 정상 공식+보완 결합과 증강 metadata 회귀를 시험한다. 관련 테스트 우선, 여러 종류와 공통 가져오기 경로 영향 검토 후 필요한 전체 회귀를 결정한다.
4. 기존에 확보한 실제 16.22.1 한·영 공식 자료에서 ID 충돌 0건을 재확인하고, 정상 가져오기·출력 수가 보존되는지 임시 경로에서 확인한다. 이미지·실제 보완 자료는 별도 증거가 없다면 미검증으로 기록한다.
