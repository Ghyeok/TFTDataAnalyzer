# Current flow and questions
ReadRecords parses each official language document before selecting set-specific records. It uses an internal id if present or falls back to property name, then stores result[id] without checking if already present. Champions are also read for set prefix discovery. Translation alignment later joins same id ACROSS languages; this must remain legal. Existing validator detects duplicate catalog IDs too late because the dictionary erased the collision. Some source documents contain historical sets and generic entries outside the selected set; rejecting every collision anywhere in a whole file can block an otherwise usable selection. Choosing the first or last without explanation can hide conflicts. Identical rows and different rows may deserve different treatment only if equality and provenance have an exact testable definition; avoid assumptions. Existing 16.22.1 augment-container duplicate metadata exception must remain narrow. The existing error channel and UI import report can convey bounded diagnostics, and failed parsing must never publish partial catalog or overwrite existing files.
Review policy for conflict detection scope before versus after filtering, false-positive availability impact, missing/empty ids and different keys with same id, locale separation and reproducibility, actionable privacy-safe diagnostics, deterministic ordering, TDD/QA cases and explicit data preservation. No live APIs or altering published catalogs needed.
