# Evidence and user outcome
A TFT Unity Editor imports patch-specific Riot Data Dragon JSON and optional CommunityDragon. Existing published catalogs must remain immutable and preserve provenance. In a synthetic Unity test, an official item data object contained two DIFFERENT JSON property keys, each containing the same internal id but different names. Current official adapter assigns each row into a dictionary by id, so the second row silently overwrote the first; output one item with no error. This was reproduced once on the actual parser (synthetic only). JSON duplicate-key detection does not detect it. The actual 16.22.1 official source files, both locales and four document kinds, were separately checked and showed 0 repeated internal ids. No claim other versions have or lack collisions.
Goal: prevent silent data loss and clarify the issue in the import report while keeping non-conflicting imports usable and protecting existing catalog files. New behavior has not been approved. No player or secret data.
