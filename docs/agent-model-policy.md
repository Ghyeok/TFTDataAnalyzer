# 에이전트 모델 선택 상세 지침

모델별 기본 수준과 공통 규칙은 [AGENTS.md](../AGENTS.md)에서 관리한다. 이 문서는 선택이 애매하거나 단계별 배정·사용량 비교가 필요할 때 참고하는 판단 예시다.

## 작업 시작 시 판단할 네 가지

1. **정답이 명확한가?** 입력·출력과 완료 조건이 명확하면 가벼운 모델로 시작할 수 있다. 요구사항이 불명확하면 먼저 범위를 확인한다.
2. **틀렸을 때 영향이 큰가?** 기존 카탈로그 손상, API 키 노출, 개인정보 저장으로 이어질 수 있으면 설계와 검수에 Astra · High를 우선 고려한다.
3. **여러 구조를 함께 이해해야 하는가?** 수집기·저장소·인덱스·UI 등 여러 계층을 함께 바꾸면 복잡한 개발 이상으로 분류한다.
4. **결과를 쉽게 검증할 수 있는가?** 자동 테스트나 명확한 비교 기준이 있으면 가벼운 모델을 활용한다. 검증하기 어려운 판단에는 더 강한 모델과 독립 검수를 배정한다.

역할 이름이나 파일 수만으로 모델을 고정하지 않는다. 필요한 정보가 부족하면 먼저 자료를 확보한다. 완료 조건 누락이나 원인 불명의 테스트 실패가 반복되면 시도와 증거를 정리해 재분석한다.

## 단계별 배정 예시

| 상황 | 배정 예시 | 수준을 올리는 조건 |
|---|---|---|
| 기존 형식의 로그·문서 정리 | Luna 또는 해당 작업에서 검증된 로컬 모델 | 원인 판단이나 여러 증거 종합이 필요하면 Sol |
| 범위가 명확한 기능 구현 | Sol · Medium | 여러 모듈·예외·복구 처리를 함께 변경하면 High |
| 카탈로그 식별 구조 변경 | Sol · High로 구현, Astra · High로 설계·검수 | 데이터 손상 가능성이나 계약의 모호함을 먼저 해소 |
| 경기 데이터 익명화 | Astra · High로 위험 경로 검토, Sol · High로 구현 | 식별 정보 잔존 여부를 독립 검수하고 쟁점을 재검토 |

위 예시는 모든 모델·에이전트를 호출하라는 지시가 아니다. 승인된 작업 범위와 [개발 워크플로](../Assets/Plan/Workflow/README.md)에 필요한 역할을 수행한다. 단순 계산, 해시·JSON 검사와 테스트 실행은 일반 프로그램과 테스트 도구로 처리하고 LLM은 필요한 해석과 판단을 맡는다.

## 전환과 비용 평가

- 실제 사용 가능한 모델·추론 설정으로 배정한다. 권장 모델을 사용할 수 없으면 가능한 대안과 차이를 기록한다. 실제 전환 여부를 확인할 수 없으면 미확인으로 표시한다.
- 품질이 안정적으로 검증되는 반복 작업은 가벼운 모델과 같은 조건으로 비교 실행한 뒤 기본값을 낮춘다. 로컬 모델도 해당 작업에서 직접 평가한다.
- 한 번의 응답 비용보다 **검증을 통과한 결과까지의 총사용량·시간·재작업**을 기준으로 비교한다. `xhigh`·`max`는 High 대비 개선 근거를 함께 기록한다.
- 작업 기록에 완료 조건, 선택 이유, 실제 모델·추론, 변경 이유, 확인 가능한 사용량·시간과 최종 검증을 간단히 남긴다. 작은 작업마다 별도 문서를 만들 필요는 없다.
- API 요금과 구독 사용 한도는 구분한다. API 단가로 Plus 구독 한도의 차감량을 추정하지 않는다.
