# 에이전트 모델 선택 상세 지침

모델별 기본 수준과 공통 규칙은 [AGENTS.md](../AGENTS.md)에서 관리한다. 이 문서는 선택이 애매하거나 단계별 배정·사용량 비교가 필요할 때 참고하는 판단 예시다.

## 작업 시작 시 판단할 네 가지

1. **정답이 명확한가?** 입력·출력과 완료 조건이 명확하면 가벼운 모델로 시작할 수 있다. 요구사항이 불명확하면 먼저 범위를 확인한다.
2. **틀렸을 때 영향이 큰가?** 기존 카탈로그 손상, API 키 노출, 개인정보 저장으로 이어질 수 있으면 설계와 검수에 Sol · High를 우선 고려하고 독립 검수와 실제 검증을 수행한다.
3. **여러 구조를 함께 이해해야 하는가?** 수집기·저장소·인덱스·UI 등 여러 계층을 함께 바꾸면 복잡한 개발 이상으로 분류한다.
4. **결과를 쉽게 검증할 수 있는가?** 자동 테스트나 명확한 비교 기준이 있으면 가벼운 모델을 활용한다. 검증하기 어려운 판단에는 더 강한 모델과 독립 검수를 배정한다.

역할 이름이나 파일 수만으로 모델을 고정하지 않는다. 필요한 정보가 부족하면 먼저 자료를 확보한다. 완료 조건 누락이나 원인 불명의 테스트 실패가 반복되면 시도와 증거를 정리해 재분석한다.

## 단계별 배정 예시

| 상황 | 배정 예시 | 수준을 올리는 조건 |
|---|---|---|
| 기존 형식의 로그·문서 정리 | Luna 또는 해당 작업에서 검증된 로컬 모델 | 원인 판단이나 여러 증거 종합이 필요하면 Sol |
| 자료를 바탕으로 한 문서 작성·수정 | Terra · Medium | 복잡한 판단이나 충돌하는 증거의 통합은 Sol |
| Unity 화면·이미지 확인과 정해진 화면 작업 | Terra · Medium | 결과를 직접 확인하고 기존 창·데이터 보존을 검증하며, 복잡한 원인 분석은 Sol |
| 입력과 완료 조건이 명확한 좁은 코드 수정 | Terra · Medium | 적절한 회귀 테스트를 실행하며 여러 모듈·복구 처리가 얽히면 Sol |
| 범위가 명확한 기능 구현 | Sol · Medium | 여러 모듈·예외·복구 처리를 함께 변경하면 High |
| 카탈로그 식별 구조 변경 | Sol · High로 설계·구현·독립 검수 | 데이터 손상 가능성이나 계약의 모호함을 먼저 해소 |
| 경기 데이터 익명화 | Sol · High로 위험 경로 검토·구현·독립 검수 | 식별 정보 잔존 여부를 독립 검수하고 쟁점을 재검토 |

위 예시는 모든 모델·에이전트를 호출하라는 지시가 아니다. 승인된 작업 범위와 [개발 워크플로](../Assets/Plan/Workflow/README.md)에 필요한 역할을 수행한다. 단순 계산, 해시·JSON 검사와 테스트 실행은 일반 프로그램과 테스트 도구로 처리하고 LLM은 필요한 해석과 판단을 맡는다.

## Claude 대응

2026-11-16 사용자 확정. Claude 환경(Claude Code 등)에서는 아래 대응을 따른다. 등급 위치·가격·공식 권장 용도를 기준으로 맞춘 프로젝트 판단이며, 두 공급자 모델을 같은 조건에서 비교한 결과는 아니다.

| GPT 지정 | Claude 대응 | 메모 |
|---|---|---|
| Luna · Low | Sonnet 5.5 · Low | Haiku는 사용하지 않는다. |
| Terra · Medium | Sonnet 5.5 · Medium | 시각 추론·화면 조작 배정을 포함한다. 여러 단계의 코딩·도구 사용은 `medium`에서 시작하라는 공식 권장과 같다. |
| Sol · Medium | Opus 5.5 · Medium | Opus 5.5의 기본 effort가 `medium`이다. |
| Sol · High | Opus 5.5 · High | 기본값보다 높으므로 명시적으로 지정한다. |
| Astra(사용 안 함) | Fable 5.2(사용 안 함) | 사용자가 필요하다고 판단해 요청할 때만 사용한다. |

- 추론 수준은 Claude effort `low`·`medium`·`high`·`xhigh`·`max`에 같은 이름으로 옮긴다. 모델별 기본값이 다르므로(Opus 5.5 `medium`, Sonnet 5.5 `high`) 표의 수준을 명시적으로 지정하고, `xhigh`·`max`는 같은 규칙으로 개선 근거가 있을 때만 쓴다.
- Claude Code 서브에이전트는 Agent 도구의 `model`(`sonnet`·`opus`)과 `effort`로 지정하고 실제 실행값을 기록한다.
- 상대 비용 참고(API 단가, 100만 토큰당 입력/출력): Sonnet 5.5 $2/$10, Opus 5.5 $4/$20, Fable 5.2 $8/$40. 구독 사용 한도 차감량 추정에는 쓰지 않는다.

## 전환과 비용 평가

- 실제 사용 가능한 모델·추론 설정으로 배정한다. 권장 모델을 사용할 수 없으면 가능한 대안과 차이를 기록한다. 실제 전환 여부를 확인할 수 없으면 미확인으로 표시한다.
- 사용자 요청에 따라 Astra와 Claude Fable은 대안으로 선택하지 않는다. Fable은 사용자가 직접 요청한 경우에만 사용한다. Sol이 필요한 위험도 높은 작업에서 Sol을 사용할 수 없으면 대체 모델의 한계와 검증 가능성을 확인하고, 안전한 검증이 불가능하면 작업을 보류한다.
- 품질이 안정적으로 검증되는 반복 작업은 가벼운 모델과 같은 조건으로 비교 실행한 뒤 기본값을 낮춘다. 로컬 모델도 해당 작업에서 직접 평가한다.
- Terra와 Sol 비교가 필요한 경우 동일한 입력과 추론 수준을 사용한다. 문서는 사실·대상 독자·표현을, 화면 작업은 저장 결과와 보존 여부를, 코드는 회귀 테스트를 평가한다.
- 한 번의 응답 비용보다 **검증을 통과한 결과까지의 총사용량·시간·재작업**을 기준으로 비교한다. `xhigh`·`max`는 High 대비 개선 근거를 함께 기록한다.
- 작업 기록에 완료 조건, 선택 이유, 실제 모델·추론, 변경 이유, 확인 가능한 사용량·시간과 최종 검증을 간단히 남긴다. 작은 작업마다 별도 문서를 만들 필요는 없다.
- API 요금과 구독 사용 한도는 구분한다. API 단가로 Plus 구독 한도의 차감량을 추정하지 않는다.
